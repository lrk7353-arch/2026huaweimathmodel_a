## 路线A：官方本地接入，供后续直接执行

[CANNLab官网](https://gitcode.com/org/cann/cannlab)明确支持WebIDE和本地VSCode双接入。官方[CANNLab Dev Space插件](https://marketplace.visualstudio.com/items?itemName=atomgit-cloudenv.CANNLabDevSpace)会通过平台建立连接，并给Remote-SSH写入专用配置及Include项。

用户已在本机完成官方插件和账户登录授权。本次使用已有配置中的别名和官方转发引导，没有读取私钥内容或改写配置。SSH复用验证成功，SCP也已用于传入脚本和回收JSON。后续保持该实例和官方连接可用即可；实例重建或转发变化时，重新读取平台生成的配置，不固化临时本地端口。

插件的官方声明同时说明，它会对托管实例生成关闭SSH主机密钥检查的配置。涉及这项连接安全设置应知情选择；本轮没有自动安装插件、写入SSH配置或修改主机校验。优先保留可验证的主机身份，而非额外添加忽略检查参数。

非交互SSH并不自动继承网页终端的CANN环境。远端命令采用以下顺序，在单次进程中加载环境，不修改全局配置：

```bash
source /home/developer/Ascend/cann-9.0.0/set_env.sh
python3 /home/developer/ascend-lab-codex-1z1yBI/stage0.py --out /home/developer/ascend-lab-codex-1z1yBI/results_new
timeout 120 python3 /home/developer/ascend-lab-codex-1z1yBI/torch_smoke.py --out /home/developer/ascend-lab-codex-1z1yBI/torch_smoke_new.json
```

这些是复现示例，日常由助手通过SSH执行；输出路径必须换成未存在的名称。实际已归档结果为`results_env/report.json`和`torch_smoke.json`。本轮验证使用管理编号3对应的唯一可见逻辑设备0。

## 路线B：服务器拉取固定版本入口，一次运行一批

此路线保留为备用。用户截图中原始`curl`连续五分钟下载0字节，说明当时还没有取得脚本，后接的Python未执行；这不等于算子或NPU出错。此前命令未加连接/总时限，容易长时间卡住。重试网络下载时至少使用`curl -fL --connect-timeout 10 --max-time 60 --retry 1 --retry-max-time 120`，成功后才运行；当前已经改走SCP，不再依赖远端访问GitHub Raw。原终端若仍挂着这条下载命令，可用Ctrl+C结束。

助手准备版本固定的程序，服务器通过已有出网通道下载；用户只负责启动该批次和取回结果包。代码、参数扫描、正确性检查、日志和统计由程序负责。下一批根据反馈再更新，不要求逐个算子手工输入命令。

已交付的`tools/ascend910b/stage0.py`是**首阶段环境采集入口**，尚不是完整性能实验包：

- 查询CANN编译器、profiling工具及有限范围的SDK文件；
- 在最多30秒的子进程中调用ACL初始化、可见设备数和SoC查询；
- 不设置设备、不分配显存、不运行算子、不安装软件、不启动监听端口；
- 输出report.json和tar.gz结果包；报错写入报告，不冒充上板成功；
- 不自动上传日志，不读取SSH凭据或完整环境变量；
- 不覆盖已有结果目录。

这个入口解决“怎样把后续实验做到一次启动”。已取得实际工具链、ACL运行时及构建路径，可以继续准备自定义Ascend C Add和首批12配置。`torch_smoke.py`额外验证了已安装框架的NPU执行与数值正确性，不替代自定义内核构建验证。

真实ACL查询和框架Add已通过。随后自定义Ascend C编译、运行、批量计时与性能采集均已完成；该段stage0描述保留为最小入口说明，完整运行方式见[实验README](../../tools/ascend910b/mechanisms/README.md)，测量结果见[实验报告](实验结论与赛题映射.md)。
