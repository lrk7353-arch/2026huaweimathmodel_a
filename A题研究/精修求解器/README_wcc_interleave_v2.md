# WCC 窗口交错 v2：保护非适用核心的表达顺序

`wcc_interleave_v2.py` 使用冻结 v1 的纯辅助函数，不修改 v1。接口同名：

```python
generate_interleave_candidates(ir, plan, *, num_cores, max_candidates=12, seed=17)
```

v1 会把所有核心交给局部管道优先调度，即使一个核心仅有一个 WCC。已观察到 010 的单WCC全V核心因此发生额外内部重排和大量spill，019的收益也含单WCC内部排序。v2只对同时满足“至少两个完整WCC、具有M和V工作”的核心运行原窗口策略。其余核心保留与基准重编码控制完全相同的原计算表达优先序；单操作SG核序也逐操作相同。非适用核心没有新的窗口/容量预测，元数据明确标记 `preserve_control`。

若输入的任意WCC跨核，则整个生成器明确返回不适用，不局部迁移、不静默改变映射。所有方案仍逐操作保留原核心归属。候选首项是原拓扑表达顺序的单操作SG重编码控制，接着窗口2/4/8与原/互补准入的最早开始策略，最后两个内存平局策略；池子不变，最多1控制+8窗口候选，精确去重后允许少于9项。

这项修复保护的是**计算优先序表达**，不是承诺非适用核心的实际时间线不变。单SG变单操作SG本身可能改变官方Step1行为，其他核心的COPY也会影响共享DDR。因此须分别比较原起点、重编码控制、窗口计划；不能声称v2所有候选必不退化。窗口适用核心仍可能在WCC内部重排，容量估计和计算预测仍为代理，官方评估决定最终成绩。

机制测试新增：单WCC/空核核心与控制逐操作顺序完全一致、两WCC核心出现真实交错、全部核心都适用时保持v1候选计划、表达顺序需要拓扑恢复时仍保护非适用核心、覆盖/核心归属/拓扑/窗口、确定性、编号无关、跨核WCC拒绝。v1的12测试和v2的9测试共同通过。
