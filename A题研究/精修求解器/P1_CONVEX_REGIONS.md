# P1 操作亲和分组与 SCC 凸区域粗化：纯结构研究

本模块没有接入冻结 v3，也没有调用官方评估器。API：

```python
generate_convex_candidates(ir, num_cores, max_candidates=12, seed=17)
# -> (list[{name, plan, metadata}], diagnostics)
```

固定候选池为两种操作亲和分配（critical_path/weight1、stable_id/weight0.25）、两种单调带指标（原计算 ASAP、整数依赖深度）、每个重 WCC 的 2N/4N/8N 个带，以及最终 P1 Task 活跃核上限 N/ceil(N/2)。N=5 时至多 24 个原始候选。亲和分配中的 500 周期通信估计只作为分组启发式，不修改 P1 的 1000/100 官方等待参数。

每个重 WCC 按 `(带, 亲和核心标签)` 分组，小 WCC 保持完整；重 WCC 条件沿用冻结 selective 模块：至少 16 个 compute op，工作量至少 0.75×全图 M/V 最大工作量/N。每条 compute 依赖（包括 COPY 链收缩）必须保留。先构造分组商图，再合并完整 SCC；凝聚图成为 DAG，因此最终组在 compute 依赖偏序上凸。随后重新按 P1 EFT 分配 Task，旧操作核心标签不等于最终 Task 核心。

候选按“带指标×带数量”六个结构族轮转、族内按明确代理和下界排序，精确去重后取最多 12 个。它不是 affinity×active 的均衡析因实验；重复候选的其他来源保存在 `also_generated_as`。不能据此推断某个算子的独立因果贡献。

`plan_lower_bound` 是冻结且已审查的 P1 必要下界。这个纯 API 不接收 incumbent，也不执行剪枝；后续控制器只能在下界 **严格大于经官方验证的 incumbent makespan** 时剪枝，等号仍保留次指标改善机会。代理忽略动态 DDR、内存容量、spill 和编译执行细节；低下界不意味着能达到。

## 016 的明确负结果

这批粗带候选没有打开 016 并行。两种亲和分配在每带最初均形成 5 组，但 SCC 又全部合成一个 Task：50→10、100→20、200→40，组数均消失 80%。最终 Task DAG 的同层反链见证始终只有 1，envelope-work/path=1，P1 EFT 实际仅使用 1 核。

12 个候选的最低 LB=7,715,875，比主任务已验证的 incumbent 7,715,523 高 352；在该 incumbent 已核验的前提下全部可安全剪枝，无需花官方调用验证这批方案。更多 Task 的 LB 进一步升到 7,716,875 / 7,718,875。

这不能推断原图没有并行性：原 compute DAG 有 2440 个依赖层，同层最大宽度 12，V 总工作 7,714,975，IR compute 路径为 655,140。粗带覆盖多个依赖阶段，亲和核心标签交叉复用造成商图环，SCC 合并把原有分支重新串行化。因此下一项“极细整数深度带”研究另立模块与报告，不改这组负结果。

结构反链来自相同最长依赖深度的一组 Task，是可验证的反链见证；它不是精确最大反链。envelope-work/path 也不是实测加速比。直接原 tensor 的跨 Task route bytes 不含根输入、最终输出及 spill，不能当官方全部 COPY 流量。

## 测试

`python3 -B A题研究/精修求解器/test_p1_convex_regions.py`：8 项通过。包括跨交叉分支的 SCC 回缩反例、随机图凸性、COPY 收缩依赖、单调带、小 WCC 保留、1–5 核覆盖、确定性与输入不变。独立审查另检查 177 个随机候选：合法性、反链见证、候选上限/前缀与输入不变均通过。全部为纯图结构操作，官方调用为 0。
