# 同核 WCC 窗口交错：独立精修邻域

`wcc_interleave.py` 是只生成计划的标准库模块，不调用评估器，不修改输入。接口：

```python
generate_interleave_candidates(ir, plan, *, num_cores, max_candidates=12, seed=17)
# -> (list[{name, plan, metadata}], diagnostics)
```

目标是在 P2/P3 核内合并 Task 的语义下，保持每个原计算操作的核心归属，只改变同核多个独立 WCC 的阶段顺序。适用条件：所有原 WCC 完整落在单核，且至少一个核心有多个 WCC、同时具有 M/V 工作。若存在跨核 WCC则显式返回不适用；不将部分操作偷偷迁移。单操作 SG 只用于表达优先序，不建议用于 P1。

候选首项为 `reencode_control`：按照输入映射给出的合法拓扑顺序，把原 SG 重编码成单操作 SG；不合法的映射字典顺序用遵循原核/SG优先级的拓扑序恢复，并如实标记。这个控制不声称复原了官方 Step1 内部顺序；其效果单独报告。

其余固定候选池：窗口 2/4/8 × 两种分量入窗顺序（原顺序、M/V互补）使用预测管道最早开始优先；另加窗口 2/4 的内存释放平局优先。最多八个窗口候选，精确序列化去重后可能更少，不补重复调用。互补顺序使用 M 主导、V 主导、平衡三队列；种子只用于稳定的并列选择，不读取图路径或编号。

每核同时准入至多 W 个分量，从已满足计算依赖的 M/V 就绪堆中选择操作，局部预测开始时间为 max(该管道可用时间，原计算前驱结束)。所有 WCC 无跨核计算依赖，因此按核心连接局部拓扑序仍合法。输出覆盖每个原计算操作恰好一次，单操作 SG 的核序与全局拓扑序一致；保留原 op→core 完全相同的不变量。

活跃张量代理只按计算操作首次/末次触及估计 L1/UB 字节，忽略 COPY 预取、输出落盘、spill、内存复用边、带宽与 L2。窗口限制证明的是分量个数，**不能证明不溢出**；计算预测也不是时间下界或官方总时间。候选需要原评估器成功后才能接受。

计算量约为固定八池乘 `O(E + V·W + V log V + C log C)`，W≤8；稀疏张量使用和输出计划存储为 `O(E+V)`，同时保留候选池为至多 9 份计划。核心归属、DAG、窗口上限、无输入修改、种子确定性、重编码控制、不同文件名不影响规则等由机制测试覆盖。

## 首轮探针预注册（在首次评估之前固定）

- 固定顺序：008、004、010、019、093，全部 P2/N5，种子17。包含主要机制图、可能增加 spill 的反例、共享输入与既有缓存样例，不事后只挑改善图。
- 起点统一为历史 `solver/runs/full_initial_v1/results/case_XXX/simple_p2_n5_seed0.json` 的已成功 best 及对应计划，使用全部原始哈希；不读取正式实验中间最优来追分。
- 每图最多 1 控制 + 8 窗口候选，总 P2 官方调用≤45。单 worker，每次60秒，使用独立初始空缓存；重复计划内部去重不耗评估。所有候选与起点在 manifest 中先冻结，之后不根据评估结果改生成器或顺序。
- 保留全部真实 success/timeout/error。只在成功方案中按 `(Makespan, 新增COPY字节)` 选最优，并同时与起点及重编码控制比较。起点可以继续获胜。
- 若某图存在新方案相对固定起点的严格 Makespan 改善，可对该图冻结的最终胜者额外运行一次 P3；最多5次。不在P3中继续搜索。报告同一新方案的 P2/P3 硬件差异，但这不构成完整四格策略归因。
- 不把 spill 下降、命中上升作为充分优化条件；不将本历史起点精修探针混入正式v2公平曲线。独立运行结果保留全部正负例，不声称国奖或全量泛化保证。
