# P1 极细深度带与必要 DDR 下界：独立研究结果

这组实验不修改冻结 v3，不加入其公平预算曲线。它检验一个具体问题：粗带经 SCC 合并退回串行后，真正的同层反链能否恢复值得付出搬运代价的计算并行。

## 固定方法与结构结果

`p1_depth_bands.generate_depth_band_candidates(ir, num_cores, seed=17)` 是纯生成接口。仅固定宽度 1、2、4、8；整数依赖深度按最长 compute 依赖层数计算，COPY 链依赖使用原 IR 的收缩结果。每带按周期递减、M/V 等各 pipe 工作量装箱为至多 N 组，再合并分组商图 SCC。最终 Task 核心由冻结 P1 EFT 重新分配，分组标签不直接充当核心号。宽度 1 的各带是真正反链，不应需要 SCC 合并。所有计划严格检查操作覆盖和合并核心次序后的 DAG。

这里可把同层不同 WCC 放进一组，这是与先前“保留小 WCC”的粗带模块不同的补充族；没有改写先前族的结果。候选生成没有历史成绩或图号分支。

## 更强的共享 DDR 必要下界

`p1_boundary_lower_bound.boundary_ddr_lower_bound(ir, plan)` 是另一个独立纯模块，不接入冻结的 `p1_selective.py` 或 v3。

官方 `_build_scene_a_tasks` 的边界以“Task、原 tensor”为单位：有本地消费者且没有本地生产者时补一次 COPY_IN；有本地生产者，且有外部消费者、原 COPY_OUT、或没有 eligible compute 消费者时，补一次 COPY_OUT。同一生产 Task 向多个消费 Task 扇出，生产端只写一次；同一消费 Task 的多个消费者只读一次；已有本地生产者的消费 Task 不补读。

所有这些原 Task 边界 COPY 都由 Step2 保留。Step2 只扩展 ops/tensors；重命名 COPY_OUT 的输入不会改变 tensor 大小或删掉输出 DDR 端点。COPY_IN 的 producer 边和输入 DDR 端点保留。Step3 仍执行这些操作。

更关键的是，官方所有核、读写两个方向共享一个 `ddr_remaining_work` 池。每次 COPY 的初始工作量是 `max(1, ceil(size/60))`，同时执行时按 `elapsed/active_count` 减少，因此全池总服务率最多为 1 个名义周期工作量/周期。由此可用 **逐 COPY 名义时长之和** 作为 makespan 必要下界。它比最后才对总字节除以 60 更强；零字节或 1 字节 COPY 也至少占一份工作。

保守子集只计真正原 nonCOPY producer→tensor→nonCOPY consumer 的跨 Task COPY，排除根输入、最终输出和 spill。对 tensor t，令 P 为原生产 Task 集，C 为原消费 Task 集：

- 写集合：`{s in P: C - {s} 非空}`。
- 当 P 非空时读集合：`C - P`。
- 该 tensor 工作量：`(写数 + 读数) × max(1, ceil(size/60))`。

模块同时报告完整初始边界与该保守子集。它不把 COPY 收缩依赖错误地当成同一个原 tensor；COPY 链边界按官方原始邻接计算。DDR LB 与 Task LB 可取最大值，通常不能相加，因为计算和搬运可以重叠。只有 LB **严格大于** 已验证 incumbent makespan 才剪枝；相等时仍可能改善次指标。

审查位置（原官方代码）：

- `multicore_cut_evaluate_problem_1.py:120–161`：边界条件和每次 COPY 创建。
- `schedule_step2.py:407–456,480–483`：重命名保持大小，原序列及原 ops/tensors 保留。
- `schedule_step3.py:74–92`：COPY 名义时长及 DDR 端点判定。
- `multicore_cut_evaluate_problem_1.py:238–255,397–408`：共享池服务和注入工作量。

## 预注册额外预算与官方结果

`probe_p1_depth.py` 只读取已保存的 width1 两份方案，不重新生成或调参。`实验记录/p1_depth_width1_v1/manifest.json` 在调用前固定 42 项依赖源码 SHA、原始图/配置 SHA、候选原文件与精确对象 SHA、既有基准的独立复放 record/plan/gzip/verification SHA。

原授权为两份候选各一次 P1/N5、单 worker、每次 timeout 900 秒。随后明确允许必要下界严格排除候选，所以实际是 **1 次 fresh 官方调用、0 cache、0 超时/失败、1 次安全剪枝**。基准来自 `p1_selective_v1/independent_replay` 的已验证结果，本实验未重复调用，也不把省略的历史基准成本宣传成公平预算优势。

每次调用前持久化 pending 和已用逻辑预算；返回后保留完整 record。只有官方 success、raw/gzip/原计算覆盖/场景/核数/配置/时间/搬运量/源码及输入哈希均通过，且 `(makespan, added_copy_bytes)` 严格改善时才能导出新方案。

|图|状态|基准 makespan|候选 makespan|基准新增字节|候选新增字节|结论|
|---|---|---:|---:|---:|---:|---|
|003|官方 success、证据验证通过|419601|501272|3243536|21361108|时间增加 19.46%，保留基准|
|016|严格 DDR LB 剪枝，未评估|7715523|未知|0|未知|保留基准；不把下界当实测时间|

003 官方 `scheduled_copy_bytes=22,645,372`，与新模块完整初始边界统计完全相同；`spill_added_copy_bytes=0`。这表明该候选的搬运增加来自切分边界，而非 spill。官方 worker 评估约 31.56 秒，wrapper 调用约 36.66 秒，含两图终检的研究执行约 38.11 秒。完整返回值与负结果保存在 `summary.json`，没有导出任何 improved plan。

这组固定细深度族在两图上均未得到更优方案；它不能证明全部凸区域方案无效。当前证据说明，按操作层细切虽然打开了计算并行，但会付出大量每 Task 重复读写，必须把共享 DDR 必要工作量纳入选候选判断。本轮停止，不扩大候选、图或评估预算。

## 验证

- 粗区域机制测试 8 项通过：SCC 消环、随机 DAG 凸性、COPY 收缩、单调带、小 WCC 和 1–5 核覆盖。
- 细深度机制测试 3 项通过：width1 不需 SCC、固定宽度和核数、确定性、覆盖及输入不变。
- DDR 下界机制测试 4 项通过：扇出写一次、消费 Task 去重、本地生产、根/终端边界、COPY 链、零字节、固定带宽。
- 独立只读审查复算两图保守及完整 LB，并对 2520 个小图/合法分区组合按逐 Task 原始布尔条件对照，全部一致；覆盖多个生产者、COPY 链、本地消费者与 COPY_OUT 同时存在及 0/1/59/60/61 字节，另 40 个非法商图分区预先排除。该审查官方调用为零。
- 唯一新增官方结果通过冻结 controller 的严格验真；所有冻结输入/源哈希保持不变。
