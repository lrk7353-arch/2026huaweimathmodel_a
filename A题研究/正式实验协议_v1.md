# 正式实验协议 v1（待算法冻结后执行）

制定时间：2026-09-24。当前是后续实验的预设方案，不表示表中实验已经完成。首轮历史实验继续单独保留，不能改名充当本协议下的同预算成绩。

## 固定范围与记录

使用原版100张图、固定config及原版官方评估器。正式批次开始前冻结输入、求解器、依赖脚本及评估器哈希，记录Python版本、机器和命令。P1/P2覆盖1—5核；P3在相同核数下补齐P2/P3四格对照。记录配置核数、活跃核数、Makespan、新增COPY、缓存统计、求解时间及失败原因。

算法规则不得读取用例编号以选择特制答案。已开发的四张困难图在报告中标识为设计案例。全100图是题目规定的有限用例集，所有用例都进入最终汇总；不能从中挑出改善图报告“平均提升”。

## 两种预算分别比较

第一组比较固定调用预算，目的是回答候选设计是否有效。每个算法、每张图、每个核数与场景使用相同的官方评估调用上限；预定主档为10次，补充档为4次。重复计划在算法内部去重，不消耗重复调用；提前停止时报告实际用量。统一单次上限由图规模规则设定，并在正式执行前冻结。历史incumbent若进入比较，所有方法获得同一初始方案，并统一计入重新评估成本。

第二组比较端到端墙钟预算，目的是回答实际求解效率。使用独立空缓存、同一机器、单个求解任务相同并发数；计时从读图开始，到交付最终方案结束，包含解析、生成、验证、官方评估及选择，公共官方单核参照的计算另行报告。正式实现须在启动每次评估前传入剩余时间；当前入口只有候选数和单次上限，不直接当作这一组实验。

大图预算应由计算操作数等输入特征确定，不能根据“这张图是否容易取得好成绩”临时扩大。具体秒数先用已有耗时记录标定，在看新方法全量提升前固定，并写进该批manifest；不把未定参数写成已经执行的规范。

## 比较方法和最小消融

| 方法/消融 | 要保留的共同条件 | 待检验差异 |
|---|---|---|
| 整分量简单装箱 | 固定候选上限、原版评估 | 基础负载均衡 |
| 共享输入感知装箱 | 同一基础方案和预算 | 输入复用与分量移动 |
| 操作级列表调度 | 同一图、核数、预算 | 打开大分量内部并行 |
| 操作级去通信代价 | 同一拓扑序规则与预算 | 同步/路由估计的贡献 |
| 固定分核顺序消融 | 相同操作到核映射 | 编排顺序的贡献 |
| 局部搜索（实现后） | 相同初始方案与总预算 | 反馈邻域的实际增益 |
| P3重选方案 | 固定缓存配置与预算 | 在缓存条件下调整方案是否值得 |

不以“候选组合比单一启发式评估更多计划”作为方法优越性的唯一依据。若某消融改变了候选数量，在调用预算下补齐可比候选或同时给出预算曲线，并明确不同。

当前确定性方法不需要重复相同输出来计算标准差。若加入随机局部搜索，提前固定种子17、29、43，保留三个完整结果和求解时间；主结果同时报告中位数、范围及逐图胜/平/负，不能只选最好种子作为唯一成绩。最终提交可以保留已验证最好方案，但应与算法稳定性表分开。

## 聚合与失败

P1/P2使用题面官方整图单核参照；主表显示逐图加速比的算术平均，并保留中位数、最差分位和逐图分子分母。P3逐图计算硬件收益、缓存条件下策略收益与总收益，不能把平均硬件收益乘以平均策略收益。

每个预定配置同时列出：预计用例数、成功数、超时数、生成/结构失败数、官方执行失败数和回退数。未覆盖100图时不输出伪装成全量的均值。若新方法在预算内没有结果但公共初始方案已有正式可行成绩，单独标识“回退”，并按预先规定的初始方案成本处理，不能把失败尝试移除。

报告静态官方新增COPY与动态缓存读取统计时注明口径。核内分配改变spill或编排，可能出现加速比大于核数；这些结果逐例核验，不机械截断。模型中的估计时间或下界不作为实测成绩。

## 最终复核与交付

算法冻结后，从最终方案库按预定规则选取代表性用例做独立空缓存复评，必须包含最大规模图、最大改善图、明显退化/回退图、P3收益图和主要结构类别。全部最终计划逐个核验数据/方案/配置/官方输出哈希及输出协议。对未独立重算的成绩明确其来源，不能把哈希检查表述为再次运行了官方模拟。

交付包含方法正文、全量逐图表、主图与生成脚本、可运行求解代码、依赖与命令、最终两字段方案和相邻来源记录。是否需要特定压缩包、匿名格式和文件命名，以正式提交要求核对后执行；本协议不自行假设主办方未给出的提交规则。
