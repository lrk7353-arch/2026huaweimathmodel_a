# 强化求解实验 v3

本协议在新通用入口全量运行前固定。目标是提高全部给定图的实际官方成绩并形成可复现的计算交付。它与 `正式实验协议_v2.md` 的冻结同预算对照并存，不覆盖旧结果。论文写作、排版暂缓。

## 1. 入口和新搜索空间

通用入口为 `精修求解器/solve.py`，批量入口为同目录 `batch.py`。两者完成机制测试和有限真实 smoke 后才冻结并启动全量实验。

候选顺序：

1. 强 Component/WCC 候选，最多 6 次。
2. P1 使用选择性 WCC 分裂，最多 18 次；P2/P3 使用操作级分配，最多 12 次。
3. P2/P3 使用固定核心归属的 WCC 窗口候选，最多 9 次。默认 `mixed`：共同重编码控制优先，随后保护单 WCC 核心的 v2 与允许内部重排的 v1 交替提供唯一候选。只按既定顺序和精确计划去重选取，不读取已知图号或历史成绩。分别保留 `protected`、`unrestricted` 模式用于消融。
4. P2/P3 使用实际时间线精修，最多 30 次；P3 另有最多 18 次缓存场景精修。每轮宽度 6，最多 5 轮，轮间读取当前最优；一次停滞或重复轮不立即终止。

全流程逻辑调用上限 90。上限不是承诺每次耗尽；生成器饱和、不可用、去重、下界剪枝均可能减少实际调用。阶段预算不得重复计入或无限转移。成功的原官方评估才可按 `(makespan, added_copy_bytes)` 字典序替换最优。

初始方案默认从原始 JSON 生成，**不读当前最好方案目录或按图号选择答案**。可选提供 incumbent 的接口属于另外标记的额外预算模式，初始复评也计费，不混入本协议的从零主实验。

## 2. P1 必要下界和剪枝

固定计划的每个 Task 时长下界为：各原计算 pipe 工作量的最大值，与 Task 内直接保留下来的计算依赖路径长度的最大值。原内部 COPY 链不被错误收缩为必需的 Task 内计算路径。

将 Task 数据依赖及同核相邻 Task 顺序合并为 DAG：跨核数据依赖等待 1000，同核相邻任务等待 100；取约束最大值，不能把同时约束相加。其加权最长路径给出该计划专属下界。

只有下界 **严格大于** 当前成功方案的 makespan 才能安全剪枝。等号仍可能改善新增复制字节。此界不用于 P2/P3，不声称其他切分的全局最优下界。通信、缓存、spill 代理仅用于候选排序，不能作为安全剪枝依据。

## 3. 预定覆盖和预算

- 主实验：全部 100 图，P1/P2/P3，N=2/3/4/5，种子 17，共 1200 槽。
- 稳定性：全部 100 图，P2/P3，N=5，种子 29、43，共 400 槽。
- N=1：由 v2 独立单核诊断队列覆盖全部 100 图三个场景，逻辑 cap1、超时 900 秒。它是完整方案库的单核覆盖，不冒充 cap90 强化算法实验。P1/P2 官方 N=1 加速比记 1；实际重排时间作为诊断单列。
- 单次官方评估超时：计算操作数不超过 10000 时 60 秒，否则 180 秒。生成时间、真实失败和超时均记录。大图若需要单独恢复，必须新建明确记录的恢复批次，不能修改旧失败成绩。
- CPU 并发：按图分配，P1/P2/P3 三路分别最多 3/3/2 worker；图内按场景和核数顺序执行。等待对应 v2 有限队列结束后接续，避免额外占满机器。
- 精确官方评估缓存可以共享，命中仍计一次逻辑调用。这里不比较冷启动墙钟速度；另做墙钟实验必须空缓存、串行、无后台竞争。

本协议正式比较的是固定的通用规则在给定全 100 图的表现；此前已经研究过这些图，不能称为独立测试集。种子重复也不创造新的数据集。

## 4. 结果和证据边界

所有 100 图成功且校验通过后，才计算对应场景、核数、种子的总体均值；部分完成仅报告覆盖、失败和单例，不缩小分母。输出逐图官方单核时间、目标时间、B/T、额外搬运、spill、缓存统计、实际逻辑调用、命中和失败数、分阶段最好值。

v2 的同预算强基线/operation/trace/cache 消融继续独立完成；v3 cap90 的更好分数不直接证明 cap24 下算法更优。可报告同一 v3 运行的调用前缀曲线，但须说明其阶段分配与 v2 不同。P3 缓存硬件收益与计划变化继续依据精确同计划四格和控制实验，不能仅凭命中率解释所有提速。

`当前最佳方案` 汇总可以纳入所有正式及额外探索成功计划，以交付给定实例的当前最好解；其成绩是有限搜索组合，不代表一个新的同预算算法，更不宣称已证明全局最优。所有计划保留原官方证据和来源。
