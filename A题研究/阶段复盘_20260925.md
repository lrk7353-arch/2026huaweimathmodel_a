# A题阶段复盘：从完整方案库到稳定的统一求解方法

本复盘基于本机报告、成绩表和当前代码，只读核查后整理，未启动新实验或修改求解算法。论文仍暂缓。

**总体判断：P1已经有实质性的结构优化突破，P3也获得了可核验的缓存机制证据；当前主要缺口是方法选择、预算分配及完整流程的泛化验证。方案库成绩扎实，但还不足以据此判断获奖把握。**

**一、这一阶段实际完成了什么**

第一轮直接迭代结束时已有1227/1500份方案，第二轮补齐到1500/1500。为避免缺失配置影响比较，下表将“第二轮结束”作为完整覆盖后的起点，与第六轮结束比较。

**二、最有价值的三项技术进展**

1. **P1找到划分与并行的实质矛盾。**整分量能避免边界搬运，却可能把重分量锁在单核；逐操作细切能增加并行，又可能让搬运和等待淹没收益。张量区域划分、同核小任务合并和必要下界剪枝，使我们能有依据地选择边界。016的突破不是减少了总通信：COPY从393,218增至119,950,386字节，但并行收益超过代价。适用条件和负例同样应保留。
2. **P3从命中率转向最终完成时间，并补上配对归因。**078的新顺序在P2慢3,958周期、在P3快2,732周期；090在P2慢98周期、P3快5,833周期，说明收益确实与缓存场景交互有关。052在两场景都节省1,935周期，应归排程；017命中率11.57%→27.17%而周期不变，是必要负例。以上比较针对编码控制与选定读序候选，不是最终跨方法择优成绩。
3. **短预算试错开始有实际时间依据。**P1三张图在全新评测目录从头搜索，各完成12次新评测，用时36.2、48.2、142.3秒，均无超时。它证明代表图上可以快速迭代，但并不覆盖所有困难图，也尚无同环境冷启动对照方法的完整曲线。

依据：[第四轮结果](直接迭代/第四轮成果/第四轮结果.md)、[第六轮机制归因](直接迭代/第六轮成果/P3机制归因.csv)、[完整冷启动](直接迭代/第六轮成果/P1完整冷启动.csv)。

**三、目前最需要正视的问题**

**预算控制仍然粗糙。**P3 joint固定先给旧邻域至多4次调用，然后全部交给读序。18图对旧方法7胜7平4负，平均配对收益仅0.114%；扩展8图平均反而落后0.219%。046中旧方法得到73,405，joint仍为76,087；078也错失旧方法的改善。010读序候选池耗尽后只用10/12次，余额没有回流。P1的阶段额度、85%张量代理门槛和固定粒度也有类似的策略选择问题。

**优化反馈不充分。**读序候选从起点一次生成；接受新方案后，没有重新诊断首读核、淘汰顺序和关键等待。迁核与读序主要单向衔接，缺少在共同预算内的少量交替改进。当前关键性分数基于不完整的观测依赖，尚未完整纳入内存复用和共享带宽因果关系，不能称为精确关键路径。

**方案库与通用算法仍有距离。**累计最好结果使用了不同轮次、不同方法和额外预算。最新P3比较从已优化的第五轮方案起步，可以检验局部精修，但没有证明从新图出发的完整流程同样占优。新入口限定100个case，从头模式只接通P1；旧统一入口支持任意图和P1/P2/P3，但最新策略尚未全部整合。换电脑显式输入方案可运行，不等于全部实验已完全摆脱本机历史目录。

**验证范围不足以支持广泛领先结论。**第五轮部分规则是在看到048/014负例后调整；第六轮joint在看到两方法成绩后设计，因此这些属于开发回归。P3新读序在扩展8图对旧方法3胜5负，说明不能只展示赢家。多数方法对照集中五核；定向推广到2—4核不能替代统一预算验证。种子经常给出相同方案，不能把重复种子当作独立新图。

依据：[P3比较汇总](直接迭代/第六轮成果/P3比较汇总.csv)、[逐图比较](直接迭代/第六轮成果/P3方法比较.csv)、[预算控制实现](直接迭代/p3_joint.py)、[读序实现](直接迭代/p3_read_order.py)、[当前入口](直接迭代/solve.py)。

**四、改进优先级和验收方式**

| 优先级 | 要做的事 | 如何判断有价值 |
|---|---|---|
| 最高 | 改为共同候选队列，小批试探，按实际改善与评测成本分配余额；候选耗尽即回流；全局去重 | 保持12次总调用，用18图回归检查046/078等损失能否恢复，同时保住094/090的收益；新增结构分层组验证 |
| 高 | 每次明显改善后，用新时间线重建少量候选，交替迁核与读序 | 与一次性生成在相同预算下比较，单列生成开销；证明收益来自反馈而非更多调用 |
| 高 | 将最新策略接入统一graph/config/evaluation_dir接口，完整计入建立初解和精修成本 | P1/P2/P3都能在无历史记录的新目录从原图运行；同预算比较完整流程 |
| 高 | 代表图做质量—时间曲线：30/60/120/180秒的最好周期、首次可行时间、超时率 | 同机器、同并发、空评测目录比较；包含014等困难图，不由三张成功图概括全部 |
| 中 | 完善关键读取的阻塞链诊断及方法适用条件 | 正例078/090与负例017/052能得到一致解释；调度收益与缓存交互继续分列 |
| 中 | 建立更清楚的剩余空间指标，并用小规模精确或受限搜索校验 | 区分全局合法下界与固定划分下界；不得拿当前Task下界声称接近全局最优 |

方法选择先采用可解释规则和在线收益反馈。当前只有少量图的对照证据，复杂学习模型容易把图特征与开发集成绩记住。若后续使用学习模型，候选记录必须按整张图分组划分数据，同图不同方案不能随机混入训练与测试。

P3读序存在重复解析/校验、先生成多个完整候选再截断等潜在工程开销；先分开测量候选生成、官方构建与模拟、IO，再决定优化顺序。尚无分段证据时，不应把这些直接说成主要耗时来源。

**五、接下来怎样组织实验**

先修预算控制和反馈，用现有18图作回归。确定规则后，再在尚未用于该规则设计的结构分层图上检验；如据检验成绩修改规则，应把这批归为开发数据，并另设后续验证。历史研究已接触100图，无法把已有数据重新包装成完全未见测试集。

采用小规模、分层、逐步扩展的流程：先覆盖收益/失败/低潜力三类，再补代表性核数和时间预算，最后仅对方法结论需要的部分做全量验证。保留强Component和旧方法作为对照；输出胜平负、中位数、最差退化、可行率及结构分层结果。无需恢复旧4700配置长矩阵。

当前1500份方案和官方对应关系已核对，12项机制测试通过；这保证现有成果可用。面向高水平竞赛的下一步，应把结构划分、分配和缓存顺序组织成一套能解释适用条件、能在限时内选择方法、且经独立规则验证的算法。
