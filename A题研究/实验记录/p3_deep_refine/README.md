本轮是继承历史已验证最好方案的交付优化，不是正式 fair-v2 冷初始比较。先冻结10图的 completed operation/trace/cache/beam 选中及已完成四格P3记录，再将最好P2计划用官方P3复算，与已有P3比较决定起点。没有在运行中加入新formal结果；beam六图均在冻结前已有完整case summary，未读取partial作为最终解。

总计276/320逻辑调用，12次精确评价缓存复用、264次新worker，276条全部success；每图最多32次（包括初始化、缓存命中和最终P2补格），单worker、单次60秒。3轮每轮最多12个候选，按预注册round窗口继续；同一场景内完整原序列化计划精确去重，不为凑满预算重复调用。保留原incumbent，仅当(makespan, added_COPY_bytes)字典序改善时替换。

## 精确四格与交付

每图summary.json保存T2(π2)、T3(π2)、T2(π3)、T3(π3)，两对场景必须使用完全相同的计划hash；最终P2补评预留在每图32次总预算内。已有精确P2记录只作有来源的引用。所有10图四格完整，没有将跨计划数值混称硬件加速。最终P2补格只用于记录，不回流本轮P3选择，也不回流fair-v2。

`selected_index.json` 是简洁交付索引，包含10个最终双字段JSON路径、计划hash、官方P3/P2记录和冻结来源。`results.csv` 为逐图摘要，`case_*/all_calls.json` 保存每次逻辑调用，`round_*_generation.json` 保存所有生成候选，包括未评或去重候选。

`audit.py`没有调用评估器：逐个核验276个成功gzip的makespan/COPY/cache统计、所有方案hash、选择为已评成功P3最小目标、阶段分类、每图预算、全部源快照及冻结源码/配置/原图hash。另扫描evaluations/attempts，确认恰有276个最终record，与all_calls一一对应，无漏记、孤儿或缺record目录。四格完整且固定源hash全不变。

运行脚本在“两个初始化都失败”的未触发分支缺少部分摘要计数字段；本轮十图初始化全部成功。为不改变正在运行的已冻结源码，最终计数由独立audit从全部all_calls直接重算，不依赖该分支；也单独核查finalP2成功与四格完整性。结果见audit_summary.json。

本轮已停止。没有新增失败后重试、改参数或预算外候选；观察墙时约247.7秒，包含并行正式批次资源争用和缓存影响，不用作冷启动算法效率结论。
