四图获益都来自 `phase_band` 候选：只分裂重 WCC，依据计算依赖的最早开始位置分带，再将同带内不连通的分支分开为 Task，小 WCC 保持完整。002/003/005/009 的胜者分别为 409/83/64/85 个 Task，均使用 5 个活跃核。这说明 P1 不能只考虑少量全局大块，也不能盲目将每个操作作为 Task。

四个正例均增加了 Task 边界搬运，但最终 makespan 更短；它们是时间优先目标下的改善，不是同时减少所有代价。胜者 spill 字节均为 0。局部量化切块也有改善，但未成为本组最终胜者。

008 的 108 个小 WCC 不触发重分量拆分；新方案把每 WCC 独立成 Task，必要等待下界已高于原来的每核合并方案，因此安全剪枝，保留原计划。016 深链图未获改善，继续保留单 Task 起点；不能由此推出其全局最优。

预算上限 78，实际 **50 次逻辑评估全部 success**，其中 9 次精确缓存命中、41 次新 worker 调用。共 17 个候选被严格下界剪枝，另外有精确重复和生成器候选不足，不人为补调用。运行约 471.6 秒，期间另有后台实验，不能作为冷启动速度基准。

## 下界与核验

`精修求解器/p1_selective.py` 给出固定计划 Task DAG 的必要下界：每 Task 至少需要其原计算各 pipe 最大工作量和内部直接计算路径的最大值；Task 跨核依赖等待 1000、同核邻接等待 100。只在界严格高于当前成功 makespan 时剪枝，等号保留，以免丢掉减少新增搬运的同时间解。此界不用于 P2/P3，也不是全局最优值。

独立审阅纠正了内部 COPY 链不能直接作为 Task 内必需计算路径的边界问题，随后 12 项机制测试通过。实际 50 个成功结果全部满足对应必要下界。原图、原配置、官方源码、冻结求解源码运行前后均未改变。

随后对 **全部六个最终方案** 做独立空缓存复放，6/6 success，6/6 新调用；完整原官方 JSON（包括时间线）逐字段完全一致，输入/配置/计划/官方与包装器哈希全部一致。见 `independent_replay/verification.json`。它是确定性复现核验，不是新增独立性能样本。

## 文件

- `manifest.json`：评估前固定的六图起点、全部计划、预算、源码与输入哈希。
- `summary.json`：全部调用、失败状态、剪枝理由和接受过程。
- `case_*/selected.plan.json`：原官方可读取的两字段计划。
- `independent_replay/`：六次空缓存复放证据。
- 实现：`精修求解器/p1_selective.py`；控制器：`实验记录/run_p1_selective.py`。

本轮的 4 改善 / 2 保持仅针对六张预定图。全 100 图、多核数的统一规则效果由后续 v3 全量实验检验。
