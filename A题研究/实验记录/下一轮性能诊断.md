证据索引见 [下一轮性能诊断.json](下一轮性能诊断.json)。每槽保留所读 summary/checkpoint 的路径和 SHA256；另核验了 60 份原始 `.json.gz` 结果的 SHA256、Makespan 和搬运字段，提取实际计算/通信区间；35 个 P2 排序族胜者全部逐操作核对了核心归属。`下一轮性能诊断_只读汇总.py` 可重新生成快照；重跑会得到较晚覆盖量，不能与本报告时间点混称。所有方案仍以原官方成功记录为准。

## 2. P1：当前粗块确有进步，但结构覆盖不足

P1 中一个子图是一个 Task；跨 Task 数据必须外存中转，同核 Task 也不能复用 Task 内部的驻留状态。相邻同核 Task 有 100 周期等待，跨核数据依赖有 1000 周期等待。把全图某个拓扑序分为连续块虽然保证粗化 DAG 合法，却可能将许多互相独立的分支混在一个 Task，并给后继附加“必须等整个 Task 完成”的屏障。

当前生成器先按 `critical_path`、再按 `stable_id`，每种依次考虑 N、2N、4N 块及两种分配，最终取前 `max_candidates` 个。正式 P1 只允许 8 个粗块候选；前缀截断与精确去重一起决定了覆盖，较细的 stable_id 族经常未被评估。这是确定性的空间偏置，不是执行错误。其 `proxy_end = 局部计算必要工作 + IO/60 + 等待` 还把可能重叠的计算与 IO 相加，是启发式分数，**不是下界**。

|---|---:|---|---|
| 002/N5 | 261945 → 179186 | 从 1 活跃核变 5 核；最后结束的 core3 在首个/相邻 Task 前累计有 87419 周期空档 | 真实并行正例，但 Task 切点、映射与活跃核数需联合选 |
| 005/N5 | 95618 → 94524 | 两者均只有 1 活跃核；M/V 重叠 29259→31877，Task 间空档 400 | 改善来自 Task 切分改变的局部顺序/重叠，不能宣传多核并行 |
| 003/N5 | 539607 → 596716 | WCC 方案 core0 独占 383172 M、304201 V 工作，其他核很早结束；粗块方案反而 5 Task 全在 core0 | 只切 98.1% 的重 WCC，其他小 WCC 保持完整，别用全图统一分位点 |

P1 结果的 `cross_core_transfers` 列表没有 P2/P3 的细粒度路由语义，本报告未用其长度推断“无跨核通信”；上表依据 Task、`task_dependencies` 及真实 COPY 字节。首个/相邻 Task 前空档是描述性量，不等于可消除的关键路径等待；多个核的空档不能相加当作节省空间。

候选空间还存在非嵌套现象：002 P1 的 N3 方案为 171449（2 活跃核），优于 N5 的 179186。不是硬件越多必然变慢，而是不同 N 生成了不同计划。下一版可在固定最大 N 下显式枚举少量活跃核数，并将较小 N 的原计划补空核后独立评估。不能未经验证直接复用较小 N 的成绩或缓存键。

### 3.1 固定映射调整已经是主要收益来源

| 017 | Component 35496 → Trace 32681 | 0 操作（相对 Component） | 仍 0 跨核路由、新增 COPY 340992；各核 M/V 重叠都增加；单独 Operation 却为 60652 |

**不能把上述观测简化为“减少总通信等待就会更快”。** 003 的路由 release 后等待中位数反而由 765 增至 1601，最大值 31006→31180，但总时长明显下降；005 的总 M/V 重叠反而减少，时间仍从 41728 降至 39694。排序改变整个竞争时序，只有完整官方时间线决定最终成绩。release 等待、局部重叠、静态尾长各有诊断价值，均不是完整因果分解。

### 3.2 008 暴露出未覆盖的“同核多分量交错”空间

008 的 108 个独立 WCC 各有 8 个操作、8 层，最大中间张量 18432 字节。当前 P2/N5 的 Component、Operation、Trace 最佳均是 100603：无 spill、无新增 COPY，**所有核的 M/V 重叠都是 0**。core0 的 50952 个 M 周期与 48312 个 V 周期几乎串行累加。

真实片段为 M4 `[1030,2188]`，随后 V6–11 `[2188,4384]`，再 M12 `[4384,5542]`，之后另一独立分量的 M64 才 `[5542,6700]`。这显示当前优先序倾向逐分量走完。它不证明所有这些区间都能合法重叠：仍须检查同核容量及内存依赖。恰当的新邻域是保持 WCC 到核的映射，有限窗口交错多个分量的 M/V 阶段，并让原官方评估处理容量、FIFO 与竞争。

正式 trace 已有三种全局尾长/ID 顺序，但它们并不显式维护活跃分量窗口，也没有“优先填空闲 M/V 管道”的相位目标；单纯增加这三种顺序的重复轮数可能仍停滞。

### 3.3 spill 少不是时间一定短，spill 多也不等于优先优化

004/P2/N3 给出直接反例。原 Component 是 134043、spill=0；Operation 是 **132570、spill=1502208**，每个原操作核心归属相同，每核 M/V 重叠由 13608 增至 15954。增加换入换出与更多计算重叠并存，最终有净收益。固定映射重排既能改变 spill，也能改变原 COPY 排序、管道 FIFO 和容量复用边。

021/P2/N5 则不应因 spill 大就排在深搜前列。Component 为 1250168、spill=2011136，但必要 M 工作下界已为 1238400，理论总时长改善空间至多约 **0.94%**。Operation 消除了 spill，却把新增 COPY 从 11431936 扩至 51118080，Makespan 为 1301179。保留它作为负例或节省搬运的次目标比继续追逐大幅时间提升更合理。

015/P2/N5 的最好方案 spill=0，当前 43242；单独 Operation 66411，trace 单操作移动仅持平且新增 COPY 313344→373760。应优先试原映射下的顺序/局部 M/V 互补，而不是把它误标为 spill 瓶颈。

## 4. Trace 的预算用法与停滞

90 个 P2 完成槽中，85 个只生成第 0 轮，5 个进入第 1 轮。协议允许最多 3 轮，但当前每轮最多 12 个、阶段总 cap 12，因此通常第一轮就用完。候选生成时依据该轮开始时的 incumbent；本轮早期取得新最优后，后续候选仍是旧时间线生成的一批。这符合已冻结协议，实现没有偷偷少执行，而是预算设计的实际结果。

值得独立比较的是 `12` 单批 vs `4+4+4` 三小批，保持同样初始方案、同样逻辑调用上限、同样种子，记录重编码控制消耗。小批可能过早消耗名额在控制/单移动上，未必更好；因此需要对同一固定图集整体报告胜平负，不用单个正例替代消融。

016 是小移动停滞的典型：单 WCC、2440 层、全 V；P2/N5 已从 WCC 7715523 降到 1972346，trace 移一个 13 周期操作只改善到 1972344。5182 路由及新增 COPY 40355696 基本不变，最大 release 后等待仅约 2–3 千周期。应尝试保持内部通信的连续多操作链/阶段迁移与边界交换；不能仅按最大局部路由等待反复移动一个端点。

## 5. P3 的归因要继续收紧

本快照 Cache 胜者为 6 个 `reencode_control`、1 个 `advance_evicted_read`、1 个 `advance_leader`、2 个 `useful_work_before_follower`。重编码是有价值的合法搜索方向，但不是缓存特有策略。

002/P3/N2 是 `advance_evicted_read` 族在本快照中的成功实例：126411→125561，原操作核心归属不变。但同时 spill 从 870912 减到 714240，**官方按字节计的 hit_rate 反而从 22.81% 降到 3.09%**。只能说该候选在缓存场景下有效，不能说“通过提高命中率提速”或“已证 FIFO 淘汰复读优化有效”。需要冻结两计划后补 P2/P3 四格、对应重编码控制，才能辨别收益来源。本诊断没有补评。

## 7. 可独立实现的新邻域与多保真筛选

### A. WCC 内选择性 P1 分裂

按结构触发：先确定原 WCC；只对占据主要 M/V 工作、使当前一个核心结束显著偏晚的大 WCC生成局部拓扑连续块；小 WCC 原样保留。局部连续分段保证该 WCC 内粗化 DAG 无环，整个计划仍须验证。切点同时看层宽、切边张量、双管道工作、root 输入重复；不要只有全图工作分位点。候选多样性先保留不同粒度/活跃核数/排序族，再按代理排。

可增加一个**计划专属必要下界**用于安全淘汰：每 Task 权重至少为其 `max(M工作,V工作,Task内部原计算路径)`，Task 数据依赖边添加官方同/跨核等待，核内执行顺序边添加同核等待，计算这个加权 DAG 的最长路径。每个可行执行都满足这些先后与持续时间限制，所以该值确为该计划的下界；它高于现 incumbent 时，该候选不可能改善时间。若等于 incumbent，还要考虑少搬运的次级目标，不能直接删。Task 必需 IO 若未精确证明统计方式，先不加入；绝不能把现有“计算+IO”代理当作此下界。

### B. 固定核分配的多 WCC 窗口交错

仅处理计算 WCC 完整落在同一核心的部分；显式窗口限制同时活动的分量数（如 2/4/8），每步只能从满足依赖的操作中选。候选包括分量工作互补排序、估计 M/V 管道最早可用、末次使用释放偏好。为了在 P2/P3 编码顺序，使用单操作 SG 或经验证能表达同一全局拓扑序的边界。先保留重编码控制，逐操作核对归属不变，再比较排序族；否则编码改变本身就可能解释收益。

容量估计使用 L1/UB 活跃张量字节分别计，不把窗口小就叫“证明不溢出”。原 Step2/Step3 会改变 spill 和容量复用依赖，代理只能排序，最后以原评估器为准。008 的证据适合检验本邻域；004 的反例要求不能只保留 spill 少的候选。

### C. 真实时间线引导的小链/扇出簇迁移

从结束偏晚的核心和晚到数据两端提出长度有限的前驱/后继链、同一张量的一组消费者；比较保生产者、保所有消费者、整体移链的新增路由。保留原全局顺序并单独控制重编码，再从候选中按静态 M/V 工作与结构搬运形成小型非支配集。一次迁移多个相关操作可能保留内部通信，适合 016/003；单移动只消掉一条边却新增更多扇出路由的候选不应占满预算。

### D. 三层筛选与预算纪律

1. **零层：合法性和必要下界。** 覆盖、DAG、核序及计划专属必要工作。只有被证明的下界才可安全淘汰。
2. **低成本层：代理排序与多样性。** 每核 M/V 工作、root 复制、切边字节、窗口活跃内存、同核阶段隔离、粗化 Task 屏障。它们只能排序/挑代表；不能宣称候选真实更好。若引入原 Step1/Step2 预编译，须把成本计入生成时间，并另行固定协议，不在当前冻结批次暗增免费试验。
3. **高保真层：原官方评估。** 独立记录成功、失败、超时和精确缓存命中，接受 `(Makespan,新增COPY字节)` 字典序更好的成功方案。固定逻辑预算下比较候选池，另做空缓存墙钟实验，不能把历史缓存命中速度当算法效率。

`LB=max(WM/N,WV/N,原计算路径,原始IO/60)` 只计原问题必要工作，忽略分配后的额外通信、同步、spill、争用与动态缓存时序；不是可实现最优值，也不是当前计划的精确路径。它不包含同一时段可以重叠的工作之和。对 P3，原始 IO 必须保持“必经 DDR”的统计语义；本题现有 100 图结构表中原 COPY_IN 字节等于唯一 root DDR 输入字节，但不能把任意扩展数据中的重复原 COPY 都盲目计入。
