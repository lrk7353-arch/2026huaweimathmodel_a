# 固定12图快速开发轮 v1

本轮用于实测短迭代流程的代价与局部精修反馈。图集由此前冻结的结构面板决定；P2、5核、seed17，从704份方案快照对应的已验证方案继续搜索。它是额外预算的开发实验，不能当作统一算法从零求解、全100图结论或公平同预算排名。

## 实际结果

- 12/12个短profile完成并验真；每图上限9次，总上限108次。
- 实际77次原官方评测，全部成功，0缓存命中；每图私有空缓存。
- 2个图级worker，执行段观察墙时 **25.7665秒**，包含子CLI启动及逐例后验核验；不含运行前的起点预检查。期间P1/P3正式主批次仍使用本机CPU，不能将此作为隔离环境速度基准。
- 3张图耗时进一步改善，9张保持原方案；所有初始结果重现，全部源/输入/起点证据哈希未变。

前两项以略多搬运换取更短总时间，第三项时间与搬运均减少。比较对象是预先冻结的各自起点，不声称它们超过所有正在产生的其他实验结果或达到全局最优。未产生全100图官方平均成绩。

本次面板只含741–3920个计算节点的图；不能由此推断大图或全部核数也能在26秒内完成。验证的是“小面板 + 指定场景/核数 + 继承好方案 + 少量局部候选”的开发方式确实能得到快速、可核验的反馈。复杂切分/分核/交错的新算法仍需对应探针，P2局部精修结果也不代表P1/P3。

## 证据与复现

- `manifest.json`：运行前固定面板、37项运行源闭包、12个起点及其原始官方证据、所有命令与预算。
- `summary.json`：精确调用数、计时、逐图验真与改善情况。
- `case_*.result.json`：逐图后验，包含全部新成功raw验证和账本检查。
- `case_*/`：候选计划、原官方压缩输出、pending/checkpoint/summary及保留的最好计划。

驱动源码在上级 `run_quick_development.py`；必须指定全新输出目录，固定本轮12图配置，最多2并发，不自动重试。本轮所有77份成功原始结果均验证完整计算操作/核归属/时长/场景/搬运及缓存字段。方案改进应在后续明确版本的汇总中纳入，旧704份快照未覆盖或篡改。
