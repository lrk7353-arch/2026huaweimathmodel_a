# 主批次阶段贡献分析

范围：formal_v2，seed17；每题100张图×请求核数2、3、4、5，共400配置，三题共1200配置。全部summary标记completed/success，本文从evaluations逐阶段重构累计最优，并逐配置核对其与summary.best一致。本文未重新运行评测；原始证据严格审计由主分析负责。

对照是**同一运行中分量阶段最佳（最多4个候选）**：每题336个配置实际评了4个分量候选，64个仅有1个。因此不能称全部配置“4方案最佳”，也不是尚未完成的独立component长批次。

所有“降时”以官方makespan为准，数值越小越好。每配置阶段降时率为 `(阶段前累计最佳时间 - 阶段后累计最佳时间) / 阶段前累计最佳时间 ×100%`。全体平均等权平均400个配置，包含未改善的0；阶段百分比不能直接相加。

| 场景 | 阶段 | 严格降时配置/400 | 400配置平均降时 | 改善配置内平均降时 |
|---|---|---:|---:|---:|
| P1 | operation | 47 | 0.8297% | 7.0611% |
| P2 | operation | 160 | 15.9559% | 39.8899% |
| P2 | trace | 228 | 3.5773% | 6.2760% |
| P3 | operation | 167 | 15.8345% | 37.9268% |
| P3 | trace | 209 | 3.7823% | 7.2388% |
| P3 | cache候选阶段，含重编码控制 | 232 | 0.7046% | 1.2148% |

相比分量阶段，完整链条最终严格降时：P1 47/400、平均0.8297%；P2 257/400、平均18.5236%；P3 318/400、平均18.9877%。P1另有1配置只减少COPY而时间持平；P2 trace另有1、P3 trace另有8、P3 cache另有2配置只有次目标COPY改善，不能加进严格降时数。

P2/P3 trace实际产生评测候选的配置均为388/400，上表分母仍为全部400配置。没有候选的12配置按0收益处理。

## P3必须拆开的贡献

每配置定义：

- `T0`：进入cache阶段之前的累计最佳makespan；
- `Tc`：cache_reencode_control候选的makespan；
- `Tn`：所有非control的cache候选中最小makespan（没有则视为正无穷）；
- `Tf = min(T0, Tc, Tn)`：该阶段结束的makespan；
- `Tb = min(T0, Tc)`：接受或拒绝重编码控制后保留的更好者。

计算结果：

- `Tc < T0`：198/400配置，即重编码控制本身已改善。
- `Tn < T0`：228/400配置。
- `Tf < T0`：232/400配置，阶段整体平均 `(T0-Tf)/T0×100% = 0.7045812837%`。
- **`Tn < Tb`：124/400配置**，即针对缓存的候选确实进一步超越进入阶段前方案和重编码控制。
- **400配置平均 `(Tb-Tf)/Tb×100% = 0.1245985870%`**。这是控制之后的额外平均降时。
- 232个改善中，108个的全部makespan收益已有control达到；其余124个有非control额外收益。

不能把0.7046%全部归因于缓存策略，也不能把0.1246%称为纯缓存命中率因果效应。候选会改变优先序，有些还迁移算子，因此调度、COPY与缓存行为存在耦合；识别纯缓存效应仍需同一冻结方案在P2/P3的交叉验证，以及保持其他因素一致的对照。

## 重编码控制究竟改了什么

代码cache_refine.py中，`_observed_order_and_tails`按实际计算算子的(start,end,core,id)排序；`_runs_plan`随后**把每个计算算子拆为单算子子图，并按观察顺序重建core_schedules**。

额外只读核验400个control与进入阶段前计划：400/400保持每个算子所在核不变；400/400在消除子图编号差异后的分组/核内顺序仍有变化；单算子子图格式从控制前2/400变成400/400。两个官方字段`node_to_subgraph`、`core_schedules`均可能变化，不能把它描述为“只是改编号而调度数学语义完全不变”。

官方P3 `_prioritize_task_seq`按子图顺序分桶，后续Step2溢出插入、Step3执行都受该序列影响。因此准确称呼是：**固定核分配的子图重组和优先序控制**。metadata中的changed_global_rank_count=0是相对“新提取的观察序”而言，不表示相对原输入方案没有调度改变。

## 下一步判断

1. P2/P3 operation与trace有充分的本批次增益证据，应保留为主要方法。P2 trace改善中88配置的最优候选为cross_release_dependency_tail，P3为95配置；但其是观察轨迹引导的启发式，不是已构造完整内存/DDR因果DAG的精确关键路径。
2. P1 operation3200次候选评测仅47/400配置严格改善，且77次超时，继续普遍增加同类候选性价比低。把预算集中于结构适合的选择性拆分、可靠下界剪枝及核数方案继承更有意义。
3. P3优先把“固定核映射的调度控制”分离成通用阶段，再评价缓存引导修改相对这个控制的真实增量。否则论文容易把一大部分通用调度收益误认成缓存策略收益。
4. 这里是同一顺序运行的阶段增益，不是等预算独立消融：后续阶段得到额外评测预算且依赖前序结果；P2 trace预算12、P3 trace8/cache4，不能直接用二者阶段数比较哪个机制更强。本轮还只有一个种子。
