# 071单操作移动的独立复核

仅读取`critical_transfer_v1/case_071/selected.plan.json`，在独立空缓存目录用bundled Python 3.12、原版wrapper和官方评估器，顺序运行P2/P3各一次，timeout60秒；没有搜索、改计划或扩展图集。

两次均success、`cache_hit=false`。官方配置及10个Python文件在评估前后11/11哈希均与先前provenance一致。

| 指标 | 原HEFT方案 | 新局部移动方案 | 变化 |
|---|---:|---:|---:|
| P2 Makespan | 10051 | 9792 | 减少259 cycles，2.577% |
| P3 Makespan | 8212 | 8190 | 减少22 cycles，0.268% |
| 官方新增COPY | 377650 B | 373042 B | 减少4608 B |
| 官方总COPY | 499096 B | 494488 B | 减少4608 B |
| 活跃核/配置核 | 5/5 | 5/5 | 不变 |
| 子图数 | 126 | 125 | 核游程重新压缩 |
| P3字节命中率 | 44.22% | 43.86% | 小幅降低，总时间仍改善 |

本次P2时间与新增COPY完全复现原报告。新方案P3也更快，因此P3应保留新局部移动方案作为当前已验证的较优方案，无需因担心退化而回退旧HEFT方案。这里没有修改任何已有方案文件，最终纳入求解器由主任务处理。

独立结构核验不是比较大量变化的sg编号，而是先还原每个原始操作的核心归属：741个非COPY操作覆盖完全一致，**只有原操作720由core3移到core2**。从原图独立重建按最小ID优先的合法拓扑序后，旧新mapping中的操作顺序均与它一致；使用各自核心归属进行连续同核游程编码，精确重建了旧新两份计划。其余sg编号与边界变化是同一固定全局顺序重新压缩的结果。

新方案的P2/P3比值为1.195604，这是同方案增加只读Cache后的硬件收益；不要将其与两份不同方案之间的P3改善22 cycles混为一谈。两场景的静态COPY字段保持一致，P3命中不从官方搬运字段中扣除。

结论仅限071、5核和这一次被选中的局部移动，不代表局部搜索在其他图上的泛化提升。
