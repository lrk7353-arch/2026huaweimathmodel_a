# 操作级HEFT候选的独立复核

本轮只读取`探索/runs/operation_heft_v1`中4个`selected.plan.json`，使用原版wrapper及官方代码，在独立空缓存目录串行执行P2、P3各一次，共8次，单次timeout为60秒；没有搜索或修改方案。

结果：8/8成功，8次`cache_hit=false`。四个P2成绩全部复现原报告。P3使用与P2完全相同的方案，因此下表P2/P3之比是固定方案的硬件收益，不包含重新搜索或P3择优收益。官方配置与10个Python文件的11项哈希仍与先前microtest provenance一致。

## 可支持的结论及边界

- 本轮071已经使用5个核心，区别于上轮14656 cycles的单活跃核优先序方案。10051→8212是同一个5核方案增加Cache后的实测收益。
- 051较上轮切分不仅更快，新增COPY还从7208996降至230808 B，改善了上一轮显著的通信代价。
- 049仍有明显权衡：相对上轮142424降至113685，但新增COPY由833318升至5301640 B。不能忽略次要指标，只保留时间改善。
- 数千子图在P2/P3合并为每核一个Task；不能把这些成绩直接外推到每子图一个Task的P1。
- 四图是困难案例探索，单一5核配置。未进行全100图、完整1—5核、多种子或等计算预算比较，也没有证明这些方案是最优。
- 此处只评价已选中的P2方案。未在P3上进行重新搜索，因此P3还可能有进一步优化空间，但目前没有相应成绩依据。
