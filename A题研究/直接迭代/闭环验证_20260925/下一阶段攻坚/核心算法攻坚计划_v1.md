# P1核心算法攻坚计划 v1

日期：2026-09-25。状态：计划已形成，关键事实已复核；新算法尚未实现，未启动新一轮官方实验。本次核验复用已有结果，新增官方调用为0。基点见同目录事实核验.json。

**主攻目标：针对P1薄弱图，打破不合理Task聚合造成的整块等待，通过跨旧Task边界的局部重划、核心分配和必要合并生成更好的完整方案。** 既要改变拖延完工的区域，也要使官方Makespan下降；移动数量、Task数量和代理分数均不作为成功标准。

## 一、原题约束与已核实的依据

重新读取原题可检索全文并核对官方P1实现。算法只能联合决定非COPY操作的子图归属、子图所属核心和核心内执行顺序；子图依赖图以及加上核心顺序后的执行关系必须无环。原始操作、张量、依赖及配置不可修改。P1每个子图就是一个Task，所有跨Task数据都经DDR，同核放置并不能自动免除边界搬运。M/V可并行，DDR总带宽60 bytes/cycle由所有核心共享；同步、缓存容量及自动spill均由官方评测决定。

确认以下证据，详见事实核验.json：

| 观察 | 核查结果 | 对计划的影响 |
|---|---|---|
| P1五核系统性弱项 | 平均3.595250，23图低于2，最弱10图平均1.187088 | 主攻P1弱例中的共同机制 |
| P2/P3五核情况 | 平均4.334518/4.428466，低于2的图均为0 | 本轮不同时改三套核心算法 |
| 043旧瓶颈 | 核心0的Task 4→5→6→7共3117操作，结束266766；另三核207095/110370/105170 | 候选必须触及真实瓶颈区域 |
| 四次组合失败 | 3117操作仍全部在核心0；split1024仍4Task链，split512为8Task贯穿链 | 旧Task内等操作数切块不是主要突破口 |
| 043正对照 | 换划分和相应分配达到243410，再重排243378；原瓶颈操作分到445/1023/425/1224，实测四核有重叠 | 已有可复现的机制样本，先用它校验新方法 |
| 旧Task边界可以被跨越 | 更好方案中原Task5操作最早11325开始，原Task4操作直到95047才全部结束 | 原划分产生的整块等待确实可以释放 |

以上支持043上的联合重划方向，但没有单独隔离“切分”和“分配”的因果贡献；不能把其他23张弱图一概诊断成同一病因。P2通信机制不同，也不是P1应达到的性能上限。

**成绩口径修正：原题明确单核加速比定义为1。** 历史累计表中的优化后单核比值1.001等保留为原始核算记录，正式论文的1核锚点按题目取1；2—5核仍用原始单核基准除以官方多核Makespan，不额外重归一化。P3必须另报同核数的无L2/有L2时间比，不能以4.428466替代这一指标。

## 二、攻坚对象：每张图对应一个可证伪的问题

第一批为043四核、051/047/075/064五核，共5配置。先解决043的正对照与051的小规模结构，再处理075的巨型区域、047的Task链和064的非计算开销。顺序允许按已验证诊断调整，所有图都保留结果。

| 对象 | 已知现象 | 待验证病因 | 首选改动 | 判定药不对症的信号 |
|---|---|---|---|---|
| 043/4 | 旧4Task链封住可重叠分支 | 跨旧边界重组能否由通用规则重现 | 解除链中多个Task的边界，按分支/工作量重组并联合分配 | 仍只移动原核心2/3上的非瓶颈操作；或只追平旧266766 |
| 051/5 | 1416操作全在1Task、1核，时间607628 | 聚合是否掩盖值得利用的并行，而非通信导致最优集中 | 在原操作DAG上识别独立支路，按M/V工作量形成多粒度块 | 新并行被新增DDR和同步完全抵消；不能因低加速就宣称必可优化 |
| 075/5 | 5876操作巨型Task；1129个Task不超过8操作 | 巨型Task与碎片分别是否位于真实关键执行段 | 重划大区域，保留必要支路；选择性聚合非关键碎片 | 只合并碎片而巨型Task的865344计算下界未变 |
| 047/5 | 20Task仍全部在1核，时间321049 | 串行主要来自原图依赖还是Task聚合 | 跨多个相邻旧Task按分支纵向重组，检查商图链结构 | 只切为更多串行Task，或跨核等待更严重 |
| 064/5 | 已用5核，计算工作下界仅占约34.5% | Task等待、DDR争用、重复读取或spill谁主导 | 先按轨迹分类，再选通信感知聚合/重划与启动顺序 | 算力更均衡但带宽等待或最终时间上升 |

085、048、056、068保留为同类迁移检查组，第一版候选设计不使用其新实验结果调参。这些图的基线已看过，只称迁移检查，不称未见数据。025、074是接近计算工作下界的保护样本，主要用于防止破坏已有长处。

## 三、先做一个能解释瓶颈的最小诊断模块

拟新增 `p1_bottleneck_diagnose.py`；沿用现有读取、GraphIR、评测和记录接口。第一版不另建实验执行框架。

输入为图、核数、当前完整方案及已有官方轨迹；输出区域及证据：

1. 从最后结束的Task回溯任务前驱和同核前序约束，记录实际阻挡者及并列阻挡者；另看该Task内M/V计算、DDR搬运和spill。不能只把“最后一核”整体视为根因。
2. 对候选区域统计：直接操作依赖、旧Task边界、工作量向量 `(M周期,V周期)`、边界张量、Task内/Task间等待、其余核心的空闲窗口。
3. 对Task整块等待，比较所需生产者操作完成时刻和前驱Task全部结束时刻，得到“可能释放的屏障等待”线索。它是选区代理，不是承诺可消除的时间；实际Pipe占用、DDR争用和其他依赖仍可能限制启动。
4. 标注已解释和未解释的延迟。不得把重叠的依赖等待、搬运时间、核心空闲直接相加当作Makespan分解；共享带宽争用也不能用一个静态Task关键路径完全解释。

043诊断必须复现3117操作、旧4段/拆后8段串行链和更好方案的四核重叠。然后对当前最佳243378重新诊断瓶颈，不能一直盯着已经被解决的旧Task 4—7。

“触及瓶颈”也包括解除其资源阻挡：例如减少其他核心的DDR竞争，可能让关键链变快而无需迁移关键操作。因此关键操作迁移数不是硬门槛，最终仍检查官方时间与对应等待是否下降。

## 四、核心候选：区域内解除旧边界，重新划分与分配

拟新增 `p1_bottleneck_repartition.py`。保持原portfolio和旧候选可用，新模块输出同样的完整plan及metadata。

**1. 选择区域并保留外部约束。** 每次最多两个区域：一个来自实际关键等待链，一个来自重Task/重核或通信瓶颈。区域从完整旧Task集合展开为操作集合，允许跨旧Task，逐步纳入必要的相邻Task。第一版区域上限8192个计算操作，覆盖075的5876操作大Task；超过上限就选更小的可闭合区域，不能静默截断依赖。区域外操作的归属和相对顺序保留，但其实际开始时间不冻结，完整方案重新评测。

**2. 生成两类划分。**

- 分支优先：沿真正的数据依赖支路形成块，尽量让生产者与其早期消费者同块，使独立分支可在不同核心重叠；允许块穿过旧Task边界。避免把同一拓扑层的不同分支统一打包成新的全体屏障。
- 通信优先：优先组合大张量关联、共享输入较多且不会封住关键并行的操作，再逐层细化重负载块。每次聚合检查商图无环，不能因为原图是DAG就认定任意聚合安全。

粒度以区域M/V计算工作量与核数决定，初始目标工作尺度取 `W/N、W/(2N)、W/(4N)` 三档，其中 `W=max(区域总M周期,区域总V周期)`；操作数量只限制构造复杂度。零工作、单链或无法合法聚合时保留原方案。各档是待验证的初始工程设置，不代表真实最优Task时长。

**3. 同时修复分配和顺序。** 对新Task图做限定宽度的搜索，第一版保留至多4个部分分配状态。候选状态考虑M/V资源、关键依赖完成、核心可用时间、100/1000周期调度等待，以及张量流量、共享DDR和缓存压力的估计；保留少量局部块迁移/交换。避免只以旧布局下的观测Task时长重新做一遍列表调度。

旧观测时长只用于估计；重划改变了内部调度、边界COPY和spill，不能视为新Task的准确时长。代理只用于排序与保留多样性；已有安全下界只对完成重划、分配和合并的完整候选使用，不能据中间拆分版本淘汰后续组合。

**4. 保留合并前后两版。** 对已分配的相邻块尝试减少边界搬运和切换的合法合并，保持所选迁移布局；同时保留未合并版本。P1同核Task仍经DDR，必须真正合并成同一Task才可能消除相应边界搬运。

两个区域×三档工作尺度×两类划分×合并/不合并，第一版最多24个完整候选；先用合法性、重复检查、安全下界及多样性筛选，只有少数进入官方评测。构造与代理计算也计入总求解时间。

## 五、先用小对照判断核心改动是否有效

**开发阶段：每轮5配置，每配置最多8次官方调用，两轮上限80次。** 每配置总墙钟180秒、单次评测60秒、最多2工作进程、种子17。构造/搜索累计上限30秒，包含在180秒内；超时或异常保留已经得到的可行方案，不自动重试。无新候选时提前结束，记录没用完的预算。

每配置的8次分配：

| 调用 | 内容 | 要隔离的影响 |
|---:|---|---|
| 1 | 当前最佳输入方案独立复评 | 核对起点、获得统一轨迹 |
| 2 | 旧按操作数拆分＋旧分配器 | 对照旧邻域 |
| 3—4 | 新重划两种代表粒度＋同一个旧分配器 | 新划分是否本身提供了更好的搜索结构 |
| 5—6 | 同两份新划分＋新的联合分配/顺序修复 | 增量是否来自更好的分配 |
| 7 | 对较优新联合方案做一次合法、保留布局的合并 | 合并是否抵消搬运与切换开销 |
| 8 | 固定多样性槽：第二划分族或被旧proxy筛掉的合法候选 | 代理筛选是否漏掉候选 |

第8槽的优先顺序在实现冻结前写入协议；按结构、代理和重复情况选择，不按事后实验输赢换规则。若中间候选单独不改善，仍可评它的完整分配/合并版本。若合法候选不足，不用重复方案填满调用。

上述为开发与消融，不是统一从头算法排行榜。历史输入方案成本单列，不能把它称为“8次从头求解”。043旧266766只作机制反例；当前243378才是新成果比较起点。重现243410/243378算机制校验，不算超过现有最佳。

**开发晋级门槛：至少两张薄弱图相对当前强起点降时≥5%，且轨迹能定位改进发生于原瓶颈或其等待。** 这是投入决策门槛，不是统计显著性保证。单图大胜仍可保留为定向成果，但不升级默认。两轮仍无符合条件的改善，就停止扩大此候选族，按下一节诊断调整。

## 六、结果不符合预期时，具体改哪里

| 观测 | 下一项改动 |
|---|---|
| 新候选未触及关键操作或原Task屏障链未变 | 改区域提取与跨旧边界的分支聚合，暂不改预算 |
| 重划改变结构，但新分配仍把关键分支放回同一核 | 校准依赖释放、局部交换和分配代价；在≤24个粗块的小区域用限时整数规划作代理模型参照 |
| 关键操作重叠增加，时间反而变差 | 检查新增DDR字节、争用窗口和spill，增大部分块、保留共享输入、调整合并 |
| 代理推荐经常被官方否定 | 用已付费评测记录校准排序；保留探索槽，不再提高硬过滤阈值 |
| 只在051或043等单图有效 | 检查是否依赖特殊分支形状，在同类迁移组测试结构规则；保留专项而非通用升级 |
| 弱图改善，优势图退步 | 调整基于结构/轨迹的进入条件与预算路由，在全组验证后再冻结 |

小区域整数规划只优化近似模型，它的最优值不是官方问题的最优性证书；任何推荐仍须用官方评测。第一版不把整张大图整数规划作为前置任务。

## 七、统一算法晋级：控制研究成本，不混淆成绩

先在开发组确认核心候选有效，再复用已有执行器做从头比较：

- 迁移组085、048、056、068，各3核与5核，共8配置。比较原portfolio、相同预留预算的旧精修、新联合精修三个方法，每方法总调用上限12，最多288次官方调用。当前已有成绩可用于解释，不能免费作为从头输入。
- 新旧预留方法共用8次以内的起始候选过程，剩余4次为精修：保留一个旧Task候选槽、两个不同族的联合重划候选槽，最后一槽按冻结规则用于修复或多样性探索。共用前缀即使物理复用，也在各路逻辑预算与时间内收费。原portfolio仍以完整12次作为强基线。
- 同时统计从头结果及暖启动精选成果，分别报告。不能以“原方法12次的最佳结果免费起步，再加新4次”宣称相同预算胜出。
- 迁移组至少两张不同图优于原portfolio，平均逐图加速比差为正，3核/5核各自平均降时非负，最大单配置退步≤0.5%，无未处理无效方案/错误/超时，才进入推广检查。门槛必须先登记。
- 推广检查的8张图已按新算法实现前的基线与结构选定：弱组049/044/071/082，中组090/024，强组033/014，全部覆盖2—5核；比较原portfolio与新统一版本，总预算仍12，最多768次。详见推广面板预选.json：排除开发/迁移/前期重点图，按五核基线小于2、2至4、至少4分层，再按归一化结构特征取中心及最远点，得到4/2/2张。文件冻结了名单、规则、输入哈希与门槛；正式运行前另冻结实现源码和运行配置。不能根据新方法输赢换图。旧025/074另作开发回归，其结果不冒充新保留组成绩。
- 推广组按同样两图获胜、平均加速比差为正、各核平均降时非负及最大退步≤0.5%筛选。通过后才讨论8/12/16预算曲线或1500组合发布评测；两者不自动同时扩跑。

推广面板有意增加弱图比例，其均值不能外推为100图总体收益；分别报告弱/中/强组表现，全量成绩只能由后续全量验证给出。

统一算法可按可计算特征选择候选族：重Task封住并行则重划，真实长链则偏向保持局部性，通信/碎片主导则聚合与顺序修复。代码中不能写case编号分支。任何回退只能使用该次总预算内已生成和评过的候选，不能偷用历史方案库。

全局主指标为 `平均(原始单核时间 / 当前官方多核时间)`，同时报告逐图胜平负、降时、额外COPY、求解时间和调用数。P3继续保留同核无L2/有L2对照；若要解释缓存机制本身，应另用匹配方案对照，区分缓存和划分变更的影响。本阶段不同时改P2/P3。

## 九、参考研究只提供方法部件

[Evolutionary Acyclic Graph Partitioning](https://arxiv.org/html/1709.08563)支持借鉴保持商图无环的多层次聚合与细化；其硬件和gang模型不同，不能直接把最小割目标当作本题Makespan。

[Efficient Multi-Processor Scheduling in Increasingly Realistic Models](https://arxiv.org/html/2404.15246v1#S4)的局部重排、局部整数规划与多层次方法可作候选设计参照；其BSP计算/通信阶段和NUMA代价与本题四Pipe、共享DDR争用及私有缓存不同。仅借鉴局部联合优化的结构，不采用论文收益作为本题预期。
