# P1区域重划后的接力细化

这是一轮本机热启动机制对照，使用047、075、085三张图各两种历史起点，判断旧联合细化能否接在新区域方案之后，以及两种方法是否能突破当前精选。

## 运行与查看

双击本目录的 `查看进度.command`，或在上级目录运行：

```bash
python3 show_p1_relay_progress.py
```

实验运行入口（需要项目已有Python环境）：

```bash
python3 run_p1_relay_probe.py --inputs P1接力实验_20260926/inputs/manifest.json --out P1接力实验_20260926/run_v1
```

同一输出目录禁止并发启动两份运行器。重复启动会保留已完成任务；中断候选有结果则接回，没有结果则计入中断槽位，不免费重试。恢复时重新生成同父候选队列的开销也计入剩余预算。`--seeds-only` 仅重放起点，不启动后续比较。

## 对照范围

- `legacy_joint`：旧 `p1_joint_regions` 的完整联合候选族，含phase、tensor_cap、重新分核与可选小Task合并。
- `region_joint`：新 `persistent_p1_moves` 区域重划候选族。
- 共享同一个控制器：保留当前最好；严格改善后重新生成，否则继续当前父方案队列；每个新队列round递增；完整有序方案精确去重。
- 两臂均使用官方逐核Task/操作轨迹。region本轮使用 `task_release_fallback`，没有额外重新编译观察，因此不能称为原persistent控制器的完整复刻。
- 旧族可全局重新分核，新族主要保护区域外的归属；这是被比较方法本身的差异。
- 不用代理值或下界作硬剪枝，所有实际评测保持原官方代码。

每臂最多6次新增官方调用、调度墙钟预算180秒，单候选worker最多60秒，每次生成最多12秒，2个进程并行。官方封装的准备和落盘可能让实际时间略超调度预算，实际开销完整保存。全批调度上限1200秒，起点重放另外明确计数，每个起点最多90秒。当前六份起点已通过本机官方重放；后续运行复用这六份本轮重放记录，不重复评测。

旧联合族一次生成整批候选，新区域族逐个生成；生成超时/错误与真正候选耗尽必须分开分析，不能把0评测直接解释为方法无效。

## 结果文件

- `inputs/manifest.json`：六个起点、实际历史来源与精选阈值。
- `run_v1/seeds/`：本机共享起点重放结果。
- `run_v1/arms/`：逐候选官方记录、原始trace、计划、进度、生成成本。
- `run_v1/progress.json`、`comparison.csv`：批次汇总；进行中需同时查看逐臂summary中的pending。
- `run_v1/分析汇总.json`、`逐起点对照.csv`：实验分析器生成的细分结果。

最佳值按 `(makespan, added_copy_bytes)` 字典序比较；同耗时只减少搬运与真正减少耗时分开列示。超过精选的候选必须另行独立官方复评，才能列入新增成果。

本轮只有三张独立图，六个起点不是六张图。历史获得起点的搜索成本不算作本轮新增调用，但这意味着它只能验证热启动接力机制，不能声称完整冷启动算法或100图总体提升。没有改动原默认算法、官方数据或队友已有方案。
