## 直接使用交付方案

`累计1500配置成绩.csv` 是100图×P1/P2/P3×1—5核的完整索引。`plan` 相对于本目录解析：本轮改进放在 `精选方案/`，未改变条目引用前一轮完整库。整个Git仓库克隆包含这些依赖，不需要本机历史评测缓存。

`source`、`source_commit`、有序 `plan_sha256` 和 `verification` 保留来源与验证。`source_plan` 是本机原始实验路径，仅作追溯，不是使用方案的必要输入。原始大轨迹和每次评测临时目录不入库；压缩调用记录、指标、冻结清单与精选方案入库。

仓库根目录可执行结构和账本检查（不调用模拟器）：

```bash
python3 A题研究/直接迭代/三指标联合推进_20260926/analysis/audit_delivery.py
```

该检查确认1500项完整覆盖、合法性、核心数、有序输入哈希、加速比分母和相对本轮基线不退步。新增方案另有独立官方复评记录；结构检查不能替代官方复评。

## 可选联合精修入口

Python标准库即可运行求解；绘图脚本另需matplotlib。在仓库根目录运行，例如从已交付的023/P3方案继续精修：

```bash
python3 A题研究/直接迭代/wait_search.py \
  --case case_023 --problem 3 --cores 5 \
  --incumbent-plan A题研究/直接迭代/三指标联合推进_20260926/精选方案/p3/n5/case_023_multicore_res.json \
  --policy wait_joint --budget 12 --seconds 180 --timeout 45 \
  --out /tmp/questionA-wait-023-new-run
```

输出目录必须不存在。`best.plan.json` 是本次最优解，`summary.json` 记录全部实际调用、评测失败、生成超时与墙钟。首次固定方案评测占一次预算；重复有序方案不再评，失败也计费。已有方案本身的历史求解成本不在这12次中，因此这是暖启动精修，不可冒称从头统一算法。上例仅展示可用入口，不承诺精选方案还能继续改善。

`mature`、`proxy`、`wait_joint` 三个策略保持可选；P1的新联合候选本轮没有胜过成熟精修，使用时以实验用途为限。`proxy` 仍共享新候选生成空间，只将排序偏向静态搬运/复用，不能当成删除全部等待信息的消融。

## 复现实验与统计

暖启动运行器为 `run_wait_panel.py`，固定54臂；从头运行器为本目录 `cold_compare.py`，按已登记晋级场景固定64臂。源文件摘要保存在两处 `manifest.json`。从头脚本仅是冻结研究对照，不是晋级后的生产入口。

运行器在本机可续接已完成的槽位，但新克隆没有原始槽位缓存，重新运行会产生新的官方调用和墙钟。复现前读协议，使用对应冻结提交的新工作区；程序拒绝对同一路径混入不同源文件哈希。跨机器墙钟和超时可能不同，不能把新运行悄悄替换为本报告记录。

`集中对照/全部调用.json.gz`、`从头对照/全部调用.json.gz` 和逐配置CSV保留已发生的比较证据；`归因/` 与 `主要收益归因/` 保存单因素和同方案跨场景对照；`当前P3观测.json` 是本轮基线100图，`交付100图P3五核三指标.csv` 是接收精选后的100图，二者时点不同。

`累计核数曲线.csv` 同时提供固定原单核分母、当前同场景单核方案分母；后者单核点为1。`同核P2P3累计对照.csv` 比较独立优化后的方案，不能当作同方案缓存净收益。图片/PDF为累计库曲线，不是从头算法的全量曲线。

分析脚本中的原始实验路径主要服务本机追溯；新克隆可直接读取入库的统计、精选方案并运行上面的审计与精修入口。需要重新生成完整调用归因时，应先在相应冻结版本重跑实验，而不是假定未入库的大轨迹存在。
