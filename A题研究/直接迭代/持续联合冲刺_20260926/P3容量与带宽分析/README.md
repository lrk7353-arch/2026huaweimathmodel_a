# P3容量与带宽分析交付

这份补充完成原题P3要求的容量、带宽影响分析，供队友直接整合论文。没有修改求解器、方案、原config或官方评估器，没有新增官方评估调用。

正文在[论文补充章节](论文补充章节.md)，按“容量驻留→查询时序→独立带宽→全池证据→正负例→调度含义”组织。公式编号P3-1至P3-4、表P3-1至P3-4和图P3-1为临时编号，合稿时统一替换。正文中的表格和结论对应以下可重建证据。

## 数据与范围

- `五核官方缓存事件.json.gz`：成熟从头P3五核100图的缓存事件、COPY时间线及最终驻留集合，约11 MB。由本机既有完整官方结果抽取；收集时逐文件校验完整原结果SHA256，保留与已入库selected_records的关联。
- `五核容量与时序分类.csv`：逐图miss历史、FIFO峰值/淘汰、两路径时间区间及并发数。
- `成熟从头P2P3配对500项.csv`、`核数与缓存汇总.csv`：1—5核各100图；标出两场景计划哈希是否一致。
- `既有微实验正负例.csv`：从已入库官方微实验结果提取，未重新执行；`既有微实验来源哈希.json`记录源文件。
- `事件定位索引.json`：逐图各类首次事件的数组下标和内容。复核必须保留同cycle事件顺序。
- `分析摘要.json`：来源哈希、汇总与检查结果；`official_calls_added=0`。
- `容量时序与命中率反例.png/.svg`：论文图，源数据和绘图程序一并保存。
- 046正式图的两场景固定方案对照直接引用上级[重点正负例复评.csv](../重点正负例复评.csv)及同名JSON，不改写原实验记录。

图池数据来自成熟从头版本，不是最新累计精选库：五核逐图平均命中率25.2853%、合并字节命中率34.0939%；不得与最新精选的27.7127%和31.0793%混用。P2/P3配对500项的计划可不同，只有43/100五核计划相同；整体同核比不是纯硬件加速。

## 复现与核验

在仓库根目录运行，仅使用Python标准库和入库证据，不需要本机原始评测目录：

```bash
python3 A题研究/直接迭代/持续联合冲刺_20260926/P3容量与带宽分析/build_analysis.py
```

程序核对全部100图事件的hit/miss成员状态、FIFO顺序、实际淘汰列表、占用、最终条目、字节/次数汇总和时间戳，并与原官方最佳记录中的指标和方案哈希一致。同时核对1500份来源记录的config及官方Python文件哈希。它是保存轨迹的描述性复核，不模拟候选或不同配置。

验收时另在独立临时目录仅放入上述证据、原记录和官方源码，重新运行分析；7份CSV/JSON输出与工作区逐字节一致。两个Python文件通过语法检查，论文图已检查可读性。这个检查只验证证据重建，不代表重新评测算法。

绘图另需Matplotlib：

```bash
python3 A题研究/直接迭代/持续联合冲刺_20260926/P3容量与带宽分析/plot_analysis.py
```

`build_analysis.py --collect-local`仅用于首次从已有本机官方结果抽取紧凑事件包；新克隆无需执行此参数。它读取旧结果，不调用官方模拟器。

## 论点与证据对应

|论点|直接证据|判断与边界|
|---|---|---|
|命中查询不刷新FIFO；完成时尝试插入|官方P3第416—434、487—510、539—590行|支持；条目已被淘汰时，命中读取完成也可能重新插入，不能省略驻留阶段|
|驻留条件须计目标自身大小|FIFO队首淘汰代码、事件重放|支持；按实际成功插入字节计算，不能拿请求字节粗加|
|容量够用仍可0命中|046成熟五核，峰值995936 B、0淘汰、150次首插入前重复miss|支持；仅提高容量对这份固定方案无效，不能推广到改变分配后的方案|
|大量淘汰不代表有后续复用收益|095的1626次条目淘汰、0后续miss及0命中|支持；不能用淘汰数代表可节省时间|
|存在容量/驻留相关重复读取|072淘汰后再次miss共82877600 B；全池30图有此类事件|支持现象；没有测定扩大容量可收回多少字节/周期|
|DDR/L2是独立共享带宽池|官方P3第323—326、352—396、570—581行；83图有两路径区间重叠|支持；区间重叠不能作为关键路径收益相加|
|命中率提高可能使Makespan变差|原官方合成长计算3211→3225，命中率0→1/3|支持组内因果；合成图不是100图池总体收益|
|完整算法的P2/P3比较可受不同方案影响|500项配对中的same_plan标记|支持；不将整体平均同核比等同纯L2加速|
|缓存参数改变后的具体加速幅度|本轮没有参数扫描|无此结论，正文未提出相应数值|

代码依据使用本仓库原版文件：`选题分析/A题附件/code/multicore_cut_evaluate_problem_3.py`及`schedule_step3.py`第74—91行；配置、代码SHA256见分析摘要。无需引用真实910B带宽或192MiB缓存来解释题设1MiB/250B/cycle模型。
