## 使用统一入口

在仓库根目录运行，输出必须使用新目录：

```bash
python3 A题研究/直接迭代/solve_hardware_unified.py --case 9 --problem 3 --cores 5 --budget 24 --seconds 240 --timeout 60 --search-policy persistent --strict-time-limit --out 运行结果/persistent_p3_009
```

`--search-policy released`为原发布行为，也是默认；`persistent_legacy`是同初始化的旧循环对照。
持续搜索两臂默认严格截止，不会自动延长恢复。`--operation-policy`只用于原发布路径，不能与新搜索叠加。
历史精选方案不能传给该从头入口作为免费初值。

## 核心实现

- `persistent_budget.py`：结构分支、有限修复配额、局部改善和继承访问次数。
- `persistent_search.py`：共同计费、父观察缓存、短批次反馈、旧父队列续跑、日志及折中档案。
- `persistent_seeds.py`：冻结的图结构初始化；两臂相同，最多6次且100秒。
- `persistent_p1_moves.py`：操作级区域重划、跨旧Task边界、分核/顺序/安全合并。
- `persistent_p23_moves.py`：相关链迁移及补偿交换、局部存活和顺序、P3关键读时窗联动。

36项相关测试通过；两个smoke及12次warm开发调用与正式对照分账。
生成时限、同结构旧顺序、保护配额退休、相对父方案下界、未付费候选去重等审查问题已在冻结前修复。

正式协议为[正式6并发协议.json](正式6并发协议.json)，初始2并发协议及中断结果仅保留为资源预运行成本。

分析前两臂时仍检查实际初始化哈希与成功集合；时间窗口不同导致的差异不能归因于循环本身。

每个算法都从原始图开始，B24/240秒/单评估60秒，官方代码/输入/config不变。
所有失败与缓存调用计费；生成成本另外记录且计入总时间。
只从本次付费候选中导出最佳及慢1%/3%时的最低新增COPY方案。
