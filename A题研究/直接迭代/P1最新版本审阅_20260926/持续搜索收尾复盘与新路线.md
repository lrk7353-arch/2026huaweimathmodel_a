# 持续搜索收尾复盘与新路线

2026-09-26。依据队友《最终结论与接手交付.md》、远端 `codex/continuous-search-delivery` 的 `fea72e6`、正式调用账本和求解源码。本次只读复算与方案分析，未启动新官方实验，未改变求解器或默认方案。

**判断：队友停止扩大本轮持续控制器的决定合理，但现有证据不支持“方法已经到头”。最值得先验证的遗漏是：新 P1 路径替换了候选算子菜单，没有保留旧版有效的 phase 细化。应先验证新旧算子的接力，再考虑关键区域的局部联合求解。**

此前审阅中的“等待完整实验”“尚需确认是否真正跨 Task 修改、持续深入”等不确定性，已由这次最终记录消除；本报告更新这些判断，保留此前探针结果的原范围。

## 1. 已完成的工作与收益口径

正式实验75配置×3臂，共225臂全部结束，224臂获得合法方案。去重正式调用4901次，其中4857成功、44超时。唯一无合法方案的是087/P1/5核的成熟臂，不能忽略失败后声称成熟方法处处成功。

|P1|3.90752408|3.92283844|0.3919%|
|P2|4.72602370|4.73072391|0.09945%|

37项更新中，成熟路径贡献7项、新初始化＋旧循环贡献25项、新持续循环贡献5项。36项减少时间，1项同时间减少搬运。它们全部独立官方复评通过，但不能把37项都归功于新循环。

这是多轮累计精选的变化，不是新算法独立从头运行1500配置的结果，也不是官方总分。最终1500份中37份本次更新、1463份继承既有验证。

在共同初始化设计的五核面板上，新循环相对旧循环：P1为4胜3平6负，P2为7胜4平8负，P3为4胜3平12负。P3均值主要由046拉动；排除046作敏感性分析，剩余18图的逐图时间比几何平均收益约0.1132%。这些历史图均参加过开发，不是盲测。

P1排除实际初始化不一致的054、058后仍退步；所以仅靠修正初始化公平性不能解释结果。低核与补充回归也出现退步，不应将新循环晋级为默认。

## 2. 最重要的新发现：旧强算子没有进入新 P1 路径

`persistent_search.py:308–340` 的 P1 算子菜单为 `joint / legacy / insertion`：

- `joint` 实际调用 `persistent_p1_moves`，即新的区域重划。
- `legacy` 实际仅调用 `p1_task_refine`，不包含旧 `p1_joint_regions` 的 phase 系列。
- 旧联合候选在 `refine_regions.py` 转入 `p1_joint_regions.generate`，包含 phase、tensor_cap、整体重新分核与可选小 Task 合并。

因此，“同起点的新旧循环比较”同时更换了控制策略和候选算子，属于完整算法对比，**不能据此单独判定持续反馈控制器没有价值**。这是设计上的算子替换，不应未经证实称为程序 bug。

复算13张五核P1图的付费调用：

|路径及候选族|付费调用|刷新本实验臂当前最好|
|---|---:|---:|
|旧循环 phase|111|70|
|旧循环 tensor_cap|24|2|
|新循环 affinity|79|9|
|新循环 branch|29|3|
|新循环 phase / tensor_cap|0|0|

这里的“刷新当前最好”仅指该实验臂，**不是突破历史累计精选库**；自适应轨迹的事件也不是独立随机样本，不能把70/111当作可泛化成功概率。

两个例子更清楚：

**047：旧方法仍有很强的细化能力。** legacy与persistent的共同初始化最佳均为322435周期。旧循环第7—24次付费调用连续18次用phase改善，最终160151；新循环24次调用没有phase，最终317205。新方案搬运更少，执行却慢98.07%。成熟臂不共享上述初始化，不能称三臂同起点。

**075：新方法可能适合大步重划，旧方法适合接力。** legacy与persistent共同起点1410559。新区域方法在第9次调用已到724319；旧循环到第12次才到722885，但之后继续下降至424934。新路径缺少phase，最终678468。两条独立轨迹支持接力假设，尚未证明把phase接在724319这个具体方案后一定有效。

085也说明新区域算子值得保留：它从旧循环2218649进一步到2081783，但当时累计精选已有873645；只对弱父方案改善不够。

## 3. 这次结果否定了哪些旧解释

- “没有真正改 Task”：不成立。P1的182个成功联合候选中180个改变划分，111个跨越旧边界。
- “没有连续深入”：不成立。连续局部改进深度到4，旧父方案实际续访416次。
- “主要是搜得不够久”：没有证据。P1新路径完整墙钟中位数约206秒，生成阶段已记录中位数约48秒。
- “搬运少、命中率高一定更快”：不成立。047是少搬运却显著变慢的直接反例；累计P3时间改善时平均命中率还略降。

候选层面，P1有86次比直接父方案快，只有13次刷新本臂当前最好；P2是141与11，P3是123与9。即局部变好的候选中约85%—93%仍没追上该臂好解，更不用说历史精选。不能把“改善父方案的次数/深度”当主要成功指标。

这支持减少无望分支的预算，但不支持拿父方案的固定分区下界直接剪掉所有可重划后继：改了分区，下界适用对象也变了。

## 4. 优先路线一：区域重划后接 phase 细化

通俗说，新算子负责重新安排一大片工作，旧phase负责把仍然拖住后续任务的大块拆开、重新排核。它们目前没有在新路径中组合使用。

实施重点：

1. 把旧phase作为明确命名的候选族接入，不能把现有 `legacy` 标签误当作已经覆盖。
2. 保留成熟phase预算；区域重划只有产生值得继续的中间方案时才接力细化，所有调用仍计入同一个上限。
3. 保留外部区域约束的差异：旧phase会全局重新分核，新region偏向固定区域外归属。接力可能破坏前一步的收益，必须实际复评，不能假定兼容。
4. 做同起点、同候选菜单、同预算的控制器对照；另做“仅phase”与“region→phase”的算子组合对照，避免再次混淆两种因素。

**首轮建议仅做定位实验，而非全量铺开：** 047、075、085各选两类已付费起点（较优区域中间解、现有强解），形成6个共同起点；每起点两臂，每臂最多4—6次新增官方调用，共48—72次上限。先检查接力是否在同一个具体计划上生效，再决定是否补充从头公平对照。

这些是热启动诊断，不能包装成从头成绩。单次超时、生成和观察必须计入总墙钟；设置整批硬时间上限，不承诺按平均调用时长机械外推的完成时间。

结果同时列出：相对共同起点、相对等预算对照、相对当前累计精选。若只修好了弱起点而没有帮助强起点，应记录机制价值，停止扩大这条提分路线。

## 5. 优先路线二：关键屏障区域的 CP-SAT 联合修复

这是比调整队列更不同的候选生成方式。仓库文档已有局部整数规划设想，但此次核查未发现可执行的CP-SAT/MILP实现与实验。

目前新P1大体仍是先划块、按关键尾长排序，再用 `schedule(..., width=1)` 贪心落核。关键决策分步作出，容易出现“单看每一步都合理，组合起来仍等待很久”。局部联合求解要同时决定：**哪些小块合为Task、Task放哪颗核、先后怎么排。**

选区不再只看最长Task和固定锚点：从官方轨迹寻找关键等待的生产者—消费者关系，优先研究“下游需要的生产操作已完成，但它所在整个Task尚未释放”的位置。粗轨迹不足时只对该小区域补取细节，成本计入生成。

首轮模型建议限制12—24个宏块、有限合法合并组，并保留当前方案可选结构。宏块是原操作的组合，不把原始算子拆开。

- 二元变量：合并组选取、组到核心归属。
- 时序变量：候选Task的起止时间和同核先后关系。
- 约束：每宏块恰好覆盖一次；原依赖保序；同核Task不重叠；按配置计入同核切换和跨核依赖等待；保留区域外Task归属与必要相对次序。
- 完整商图与核上顺序联合检查无环。仅每个合并组自身合法，并不足以证明整个候选合法。
- 目标以预测完工时间为主，边界搬运和资源负载辅助；同核Task边界仍可能产生搬运，不能按普通跨核割边模型漏算。

初始每次求解限3—10秒，最多输出2—3个结构不同的完整候选再做官方评测；这是试验预算建议，不是已验证最佳参数。若过慢，先减小区域与组选项，不默认延长搜索。

CP-SAT可以精确求解所建立的有限代理模型，但共享DDR争用、spill、内部编译排序等仍有近似，不能称赛题最优或真正的全局下界证明。相关多处理器调度研究也采用局部整数规划改善已有排程，但其BSP/NUMA模型与本题不同，不能照搬收益或成本。[研究原文](https://arxiv.org/html/2404.15246v1)；区间、先后与不重叠约束可参考[OR-Tools官方调度文档](https://developers.google.com/optimization/scheduling/job_shop)。

验证需将选区和求解器分开：相同关键区域、相同组候选下比较贪心EFT与CP联合求解，再比较新旧选区。观察官方完工时间、突破累计库的数量、实际成本；代理目标下降本身不算成功。

首选047/075/085等结构反例；加入043（合并可能伤并行）、058（分量装箱）、005/086（DDR主导）保护。先小面板证伪，再逐步扩大；不用GPU，也不先重跑1500份。

## 6. 备选与辅助路线

**分区级双父重组。** 当前 `unified_search.py:171–233` 已有区域重建与第二父多数核心归属移植，所以“首次引入交叉重组”不准确。仍可尝试的是：对两个强父方案的Task分区取公共细分，保留共同且非关键的部分，只在分歧关键区重新合并、分核与排序。区别在于融合边界结构，而非只继承核心投票。风险是产生大量碎块，必须在同一次完整候选里重新合并并验证全局无环。若局部CP建模开销过高，可作为无需新求解依赖的备选。

**从已有记录学习候选质量与评测成本。** 当前已有5维特征、7近邻的质量/成本校准，冻结经验518条、9张开发图；更强排序只是增强。可补最大Task、Task规模平方和、边界字节、关键屏障等特征，先零新增官方调用做离线分图回放，验证能否更早挑中已有好候选。历史父子依赖不能被当作免费候选，跨图划分不能被同图不同核泄漏。账本绝对路径、超时右截尾、并发与缓存耗时也要处理。CPU小模型足够，不建议以训练大模型为主线。

**独立加速模拟器。** P1官方实现有每Task扫全Tensor、每事件重建活跃Task序列的热点，值得先用6份已有粗/中/细计划做剖析。但重写后必须覆盖事件平局、共享DDR、spill与编码顺序等语义，并保持原官方最终裁判。工程风险较高，当前排在接力与局部求解之后，不能把局部函数提速当端到端倍速。

## 7. P2/P3保留的具体机会

P2没有证据支持重新大规模搜索；优先复用较好的初始化和成熟路径，低成本观察P1的候选质量/预算改进能否迁移，不直接照搬P1的Task模型。

P3仍有一个便宜、明确的覆盖问题：FIFO生成器检查的是最前3个观测目标，而非前3个可执行目标。046诊断中某些父方案到第4或第28个才有可插入独立工作。可以在时间上限内向后扫描，收集少量实际可执行且影响关键路径的窗口，再做读取移动与补偿排程。

但不能把046现有收益算作FIFO方法成功：该臂未执行FIFO联合动作。其收益来自分配/交换与共享缓存的联动。32次FIFO联合评测未刷新本臂当前最好，既说明现实现效果弱，也不足以证伪所有可修复窗口。

## 8. 建议推进顺序与停止条件

1. **先验证旧phase接力**：证据最直接，改动小，能判别新路径遗漏强算子是否造成可恢复损失。
2. **再做关键区域局部联合求解**：追求新的候选质量，而非延长现队列。
3. **同时低成本补P3可用窗口覆盖、离线候选排序**：不挤占主要官方评测预算。
4. 只有小面板出现超越强起点、包含保护图、成本可接受的收益，才扩到更大面板与完整从头验证。

停止条件不是“没有立刻拿到高分”，而是：只改善弱父方案；代理收益不转化为官方收益；突破只集中单图且保护范围明显退步；生成/评测成本抵消效果。在这些情况下记录反例，切换候选机制，不用更多同类调用掩盖问题。

真实硬件结果继续作为机制启发，官方评测继续作为题内裁判；真机带宽、缓存容量及加速倍数不替代题设参数和题内收益。

本次新增可复算证据见同目录的P1算子覆盖与收敛轨迹数据及只读复算脚本。没有新增长时间后台任务，没有合并、重置或覆盖队友分支。
