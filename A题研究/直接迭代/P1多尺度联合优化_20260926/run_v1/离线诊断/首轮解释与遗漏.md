# 首轮只读审查

来源：run_v1 的 15 个 arm、21 次成功官方候选记录、3 个父方案已付款复评记录。诊断重读 record.json、plan.json、official_result.json.gz，验证覆盖、整图与核序无环、trace 对应性、官方 makespan/COPY/模拟内存字段一致，并重新计算最终候选代理。没有调用官方评测。

## 真实候选成绩，不能以“保留父方案”冒充方法成绩

| 方法 | 047：父 159950 | 075：父 422465 | 085：父 873645 |
|---|---:|---:|---:|
| 旧 joint | **158429** | **423619** | **875987** |
| 小区域 beam | 159787 | 426445 | 876622 |
| 小区域 CP-SAT | 160007 | 426801 | 884749 |
| 大区域 beam | 159745 | 425951 | 877493 |
| 两层 | 159135 | 426342 | 878788 |

只有 047 有改善，旧 joint 仍最强。大区域相对小区域在 047、075 有益，在 085 有害；075 的相对改善仍未胜父方案。两层相对大区域直接解在 047 改善 610 cycles，在 075/085 退化 391/1295 cycles。

## 更重要的遗漏：父划分并不在模型可行集合中

父方案完整代理分别 153910.07、389382.10、793878.37；所有新细划分方法最优候选的代理都比父方案差。当前模型强制切为 20/40 个活动细块，不能联合选择“不拆/少拆”。外部接受器保留父方案，只保证成绩不退化，不能弥补求解器模型里缺少该可行选项。

小区域通常增加 16 个 Task，大区域增加 34 个。小区域 beam 的 COPY 增量为 79868/116352/360452 bytes；大区域 beam 为 119042/272384/694536 bytes。所有候选 spill COPY 均为零，所有候选的全核最大 L1/UB 占用没有变化（逐核分布可能变化）；未显示容量溢出是这批退化的原因。

再核对最终操作分组：三图两层输出的最终 partition 均与对应大区域 beam 的 raw partition 相同。这一轮两层确实做了粗化、归属投影、局部修复，但主要检验的是分组指导的核心/顺序变化，尚未检验“最终可自由合并/改变任务边界”。不能由此否定更广的多层重划路线。

## 代理错排确实存在，但不能全部归因给 DDR

候选两两比较：047 有 9 同向、6 反向；075 有 27 同向、9 反向；085 有 14 同向、0 反向、1 代理同分实际不同。三图合计 15/65 个非同分比较反向。这些是相关的小样本对比，不是推广错误率。

21 个候选与各自父方案比较，7 个改善/退化方向与代理相反。047 新方法中 3 个候选代理变差却实际变好；075/085 旧方法有代理变好却实际变差。不能只扩大 CP 搜索并认为更低的代理必然提高官方成绩。

官方 P1 本来就按整个 Task 完成释放依赖，因此“whole-Task 等待”是必须遵守的官方规则，并非应删除的建模错误。近似点是 Task 内流水、COPY 输入输出所在任务、共享 DDR 调度以及这些项在代理中的归并方式。仅凭错排不能把责任单独归给 DDR。

辅助用官方 step3_by_task.local_makespan 做同一核序 max-plus 重放，父方案得到 176581/426946/975302，均高于官方多核实际 159950/422465/873645。这说明不能把这些 isolated Task 时间直接当作共享 DDR 关闭后的真实反事实，更不能把两者差值称为 DDR 争用损失。该字段只用于诊断，详表保留。

## 今晚建议

优先完成已经确定的 beam warm + CP 上界修正，但它解决的是“同一细划分下 CP 没有达到廉价启发式”的问题，不解决强制分块开销和代理误差。

一个无需新机制的对照是：用现有 model_with_blocks 合回父 Task，只开放同样热点及 halo 的核心/顺序。零官方调用检查 4 个活动原 Task：047 代理降低 56.4 cycles；075 不变；085 降低 1000.67 cycles。若剩余调用允许，047/085 各一个候选即可检验“不支付分块代价，只改善分配顺序”。该方向仍只是假设，尚未官方验证；不建议今晚扩成新的参数大扫。

复现全部记录审计：`python analyze_p1_joint_tonight.py --run P1多尺度联合优化_20260926/run_v1`。输出包括候选完整指标、每方法真实候选最优、成对排序以及 JSON 诊断。
