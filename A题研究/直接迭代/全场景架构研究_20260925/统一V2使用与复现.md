# 统一V2使用与复现

V2提供P1/P2/P3共同的从头求解和显式热启动接口。原`solve.py`默认仍为legacy；本轮新机制通过`--engine v2`或直接运行`unified_solver.py`使用。复现冻结经验模型时使用后者。

## 已实现的算法改动

1. 从操作与逻辑张量关系构建共同结构表示；按M/V工作、独立分量、分支、边界流量和驻留代理形成不同粒度区域。
2. P1同时提供严格分支、自适应分支、通信亲和与波前划分，联合分配并保留合并/不合并的完整候选；允许跨原Task边界搜索。
3. P2按私有L1/UB驻留、去重跨核张量路由和M/V工作分配区域；接回成熟的WCC交错与官方轨迹驱动迁移。
4. P3在P2候选上增加核心覆盖和读窗口组织，并根据当前父方案官方轨迹生成读序候选。FIFO命中由官方程序决定，静态重复读仅作排序代理。
5. 最多保留6个多样父方案，做局部区域破坏、重划、重分配或父方案核心分配交叉；全过程共用调用和时间预算。
6. 用结构近邻经验排序候选；不按图编号查答案。代理值仅排序，只有必要计算/Task等待下界可用于剪枝，最终优劣由官方完工时间判定。

这不等于已经准确重建全局资源关键路径。当前区域选择仍较依赖静态负载和邻域；M/V、通信、驻留代理也不能准确模拟DDR争用、内存复用与FIFO。实际强弱以完整实测为准，不能把框架齐全写成三题已经全面胜出。

## 单配置从头求解

在仓库的`A题研究/直接迭代`目录运行：

```bash
python3 unified_solver.py --case 51 --problem 1 --cores 5 \
  --budget 16 --seconds 240 --evaluation-timeout 90 --seed 17 --stage B \
  --experience 全场景架构研究_20260925/批次C_冻结配置/结构经验.json \
  --out 运行结果/新建复现051_P1_N5
```

输出目录必须是新的。`best.plan.json`为可提交给官方评估器的方案，`summary.json`记录全部候选、失败、实际调用、耗时和选优原因。16是调用上限，不是每个配置必用16次；接近计算下界或候选耗尽时会提前停止。生成过程采用协作式截止检查，总时间是软预算，超出部分必须在汇总中披露。

Python接口`solve_unified(graph_path, scene, cores, out, ...)`接受符合题目格式的新图，配置取图所在目录的`config.txt`。命令行中的case编号只是读取官方图池的便利入口，不参与策略判断。

## 全量从头复现

```bash
python3 run_unified_campaign.py --cores 1,2,3,4,5 --variants v2 \
  --budget 16 --seconds 240 --timeout 90 --seed 17 --stage B \
  --workers 12 --adaptive-workers --concurrency-policy memory --heavy-slots 6 \
  --singlecore-baselines \
  --experience 全场景架构研究_20260925/批次C_冻结配置/结构经验.json \
  --out 运行结果/新建全量复现
```

共1500个目标配置，另加100个官方原单核基线。并发12是上限；可用内存和大图上限共同约束实际并发，不能保证一小时完成。此次运行曾修正异质任务引起的错误吞吐降档；前一段已经完成的配置通过摘要哈希、原始输入、全部非调度源码和预算相同的检查后续用，既不重复计算，也不免记原费用。`resumed_segment`保存完整来源。候选代码变化不允许走这种执行段续跑。

## 显式累计精修与跨配置迁移

`unified_solver.py --incumbent-plan 路径`可传入已有方案，初始官方复评消耗一次预算；程序不会自动查历史库。批处理使用`--incumbent-ledger CSV --incumbent-root 仓库根目录`。累计库索引中的`plan_base=delivery`相对CSV所在目录，其余相对仓库根目录。

`--transfer-summary`可显式迁移其他核数或场景的方案。程序核对图和源方案哈希，在目标场景重新官方评估并计费，另列上游求解来源；不能把其他场景的时间或上游求解成本算成免费输入。

## 成绩与交付口径

- 从头统一版本与累计最佳库分别列出；累计库不能作为统一算法的从头成绩。
- P1/P2正式平均加速曲线的单核锚点为1，同时保留实际单核求解时间。
- P3列同核数P2时间/P3时间。若两题分别优化，差异包含映射和次序变化，不称为固定方案下L2的纯收益。
- 完工时间是当前选优的第一目标，附加COPY用于同时间时优选并单独披露。少量降时却显著增大搬运的方案，仍需与原方案一并解释其取舍。
- 原题没有明确的三题合成总分公式，不把平均加速比编造成官方总分。

最终方案按问题/核数分为15个gzip JSON包，每包含100份方案；解包工具支持按逐配置账本检查官方输入哈希：

```bash
python3 unpack_unified_solutions.py 交付目录/方案分包/*.json.gz \
  --ledger 交付目录/统一算法逐配置成绩.csv --out 恢复方案目录
```

源码、配置、经验、图文件、官方程序与结果哈希均保留。大体积原始官方轨迹在本地运行目录；GitHub交付方案分包、指标、账本及证据摘要。
