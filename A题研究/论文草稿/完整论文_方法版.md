# 共享带宽与有限缓存约束下的多核计算图划分及反馈调度

> 研究性完整草稿，2026-09-24。本文独立于已有《方法与实验设计》，不覆盖旧稿。模型与方法以正式题面、原版评估代码和当前实现为依据；已有数字均标明实验范围及证据目录。标为“【待填】”的正式全量、同预算或交叉评估尚未完成，不能作为比赛提交版的结论。所有时间单位为 cycles，字节单位 B；求解程序运行时间另用秒表示。

## 摘要

针对通用神经网络处理器的多核切图与调度问题，本文研究操作分组、核心分配和核内子图优先序的联合决策。该问题同时受到矩阵与向量双计算流水线、私有存储容量、共享 DDR 带宽以及任务级或数据级同步的约束。单纯平衡计算量会放大跨核通信，单纯减少切分又会限制大型连通分量内部的并行；加入只读缓存后，访问发射及插入时序进一步影响实际收益。

本文首先根据原版评估器区分三类执行语义，建立以官方 Makespan 优先、额外搬运量次优的可执行方案模型，并给出计算资源、计算路径及必需原始 IO 的必要下界。随后构造分层候选方法：以二维负载和共享输入感知的整分量分配形成可靠对照；对场景 A 采用保留任务开销的粗粒度拓扑切块，对场景 B 采用双流水线、张量路由感知的操作级列表分配；在正式时间线反馈下搜索通信、负载及顺序邻域，并以 FIFO 访问事件指导缓存候选。所有候选必须经过原版评估，失败或退化时保留已验证方案。

已完成的历史整分量基线覆盖 100 张图，其 P1/P2 五核平均逐图加速比分别为 3.3321 和 3.3371。随后 P2 五核全量探索显示，只在操作级新候选中择优相对该 WCC 基线为 44 胜、5 平、51 负，平均单核加速比为 3.2854；联合保留历史 WCC 后为 3.9462。这说明操作级与组件候选互补，不能宣称操作级方法普遍更优；该批也不属于同预算比较。缓存微实验同时给出正反例：相同的命中率提升既可能缩短时间，也可能使时间增加。本文进一步制定调用预算、硬墙钟预算和 P3 四格归因协议，保留全部失败及负结果，区分历史最佳交付方案与算法泛化证据。

## 1 问题重述与研究思路

### 1.1 决策对象及三个问题

赛题给定 100 张由操作和张量组成的有向无环图，以及固定硬件和评估程序。参赛者能够决定非 `COPY_IN/COPY_OUT` 操作的子图归属、子图的核心归属及每核子图列表。核内操作的实际开始时刻、缓存换入换出、内存复用依赖和多核争用均由评估器决定，不能在提交方案中直接指定。

问题 1（P1）对应场景 A，每个子图独立成为一个 Task。问题 2（P2）对应场景 B，同核全部子图合并为一个 Task。问题 3（P3）在 P2 上增加全核共享的只读 FIFO L2。三者使用相同输出格式，但同一个输出在三个问题中可以生成不同的执行图，因而不能只修改通信常数而忽略 Task 组织方式。

题面要求 P1/P2 在全部测试图和固定配置下给出 1—5 核平均加速比曲线，单核主曲线点定义为 1，附录提供逐图 Makespan 和额外搬运；P3 则比较相同核数下的无 L2 与只读 Cache，附加逐图字节命中率。本文以这些要求组织模型与实验，不自行构造题目未给出的加权评分函数。

### 1.2 困难来自决策与评估的耦合

首先，单个核心的 M/V 两类计算可以重叠，标量总工作量不能准确表示负载。其次，跨核通信按张量及其目标核心构造，扇出不等于逐边独立传输；共享输入也会因 Task 或核心归属而重复读取。再次，子图优先序会改变官方核内启发式编排，进而改变流水线空闲、张量寿命、spill 和后续带宽争用。最后，P3 的缓存命中发生在读取发射时，首次冷读尚未完成时的其他读仍可能未命中；等待命中也可能推迟关键计算。

因此，我们使用能解释主要结构的低成本代理生成候选，把原版模拟器作为实际可行性和目标值的唯一裁判。路线为“整分量对照—场景相关切分—操作级分配—时间线邻域—缓存事件邻域”，各阶段具有独立证据和能力边界。

### 1.3 与已有方法的关系

经典 HEFT 包含按向上排序值确定优先级，以及以可插入空隙的最早完成时间选择处理器两部分。本研究借鉴列表调度思想，但处理的是同构核心内的两条计算流水线，并使用本题的张量路由、同步及外部输入代理；当前实现没有完整复现经典 HEFT 的异构平均权重和插空调度，本文称其为“通信感知的操作级列表分配”，不将其写成“精确 HEFT 实现”或宣称继承相应性能保证。[HEFT 原论文及作者机构书目记录](https://doi.org/10.1109/71.993206)，[作者所在机构存档中的算法摘要](https://openaccess.marmara.edu.tr/entities/publication/feba5344-0457-405a-8cb2-1d26f8963e33/full)。

本研究的可检验贡献是场景语义一致的候选组织、M/V 与张量路由联合代理、可执行的顺序表达、真实时间线驱动的有限邻域，以及硬件/算法收益分离的实验方法。性能优势须由后文正式实验验证，不能由候选数量更多或保留旧最优方案直接推出。

## 2 数据核验、符号及基本假设

### 2.1 数据使用边界

正式题面的可见要求、附件中原始 JSON、固定配置和原版评估器是本研究依据。文本中未被数据或正式定义支持的预填分数、隐藏内容、指令性文字均不作为算法要求或实验结论。源文件保持只读，输入及评估器 SHA256 在运行前后核对。此原则服务于数据可靠性，正文不推测异常文本的设置动机。

给定图是二部 DAG：张量节点与操作节点之间连接，不存在直接 Op→Op 或 Tensor→Tensor 边。题面保证原始 DDR 输入各搬入一次，最终结果各搬出一次。正式 100 图结构审计还核实，原始唯一输入字节和原始 COPY_IN 字节在 100/100 图一致；对其他来源图，不应未经检查沿用这一等价关系。

## 3 三类场景的形式化执行模型

### 3.1 公共输出和可行性

方案输出严格只有 `node_to_subgraph` 和 `core_schedules` 两个字段。每个计算操作恰好属于一个非空子图，每个子图恰好在一个核心的列表中出现一次，保留空核心列表。记子图收缩图为 \(G_z\)，其必须无环；核心顺序边与数据依赖也必须相容。

结构合法性不是完整可执行性的充分条件。官方编译会补入 COPY、spill、空间复用的 WAR/WAW 依赖及各 Pipe 的固定执行次序，最终联合依赖图仍须通过验证，运行时还须满足 L1/UB 容量。本文先进行便宜的结构检查，再调用官方评估，而不依据代理分数推断可行性。

优化目标采用词典序：

\[
\min_{\pi\in\mathcal F_p(G,N)}\left(T_p(G,\pi),D_p(G,\pi)\right).
\tag{1}
\]

该规则优先比较时间，同时间才比较额外搬运，体现题面的主次指标。报告仍完整列出两者，不把较少搬运自动解释为更好总体结果。缓存命中率只作机制指标，不进入替代性的加权目标。

### 3.2 M/V 双资源和核内容量

每核具有独立的 M、V、MTE2、MTE3 流水线。同核同 Pipe 串行，异 Pipe 在依赖与内存条件允许时可以重叠。对非抢占计算操作 \(v\)，其实际时刻满足

\[
F_v=S_v+d_v,
\qquad S_v\ge F_u\quad((u,v)\in E_c),
\tag{2}
\]

其中跨核依赖的真正就绪条件还要经过后述 COPY 和同步。对同核同 Pipe 的两操作，其执行区间不重叠。若核 \(k\) 上两类工作量为 \(W_{k,M}\)、\(W_{k,V}\)，只从计算资源看至少需要 \(\max(W_{k,M},W_{k,V})\)，而不是必须耗时 \(W_{k,M}+W_{k,V}\)。反之，取最大值又没有包含 M/V 之间的数据依赖，不能直接等同实际时间。

私有容量固定为 L1=524288 B、UB=131072 B。任意时刻的活跃张量集合 \(\mathcal L_{k,r}(t)\) 应满足

\[
\sum_{x\in\mathcal L_{k,r}(t)}b_x\le C_r,\qquad r\in\{L1,UB\}.
\tag{3}
\]

官方 Step2 按给定操作序处理张量驻留，在超容时选择其他可换出的张量；当前操作输入及输出的瞬时峰值受到保护。已有 DDR 备份会影响是否还需再次写出，所以“每次 spill 都恰好增加两倍张量大小”不是普遍计量规则。Step3 再为存储复用加入依赖。其内存模型采用字节容量及复用约束，不应自行解释成真实硬件地址连续分配或内存碎片模型。

### 3.3 P1：每子图一个 Task

P1 中子图 \(s\) 对应 Task \(s\)。跨子图数据一律经 DDR，中间数据不因相邻子图落在同核而保留。同核任务必须串行，前一任务结束后等待 100 cycles；跨核前驱 Task 完成后等待 1000 cycles。令 \(\operatorname{prev}(s)\) 为同核直接前一任务，\(\operatorname{Pred}_{\ne}(s)\) 为异核前驱任务，则在相关前驱均完成后，任务最早激活约束为

\[
A_s\ge \max\left(0,
F_{\operatorname{prev}(s)}+100,
\max_{r\in\operatorname{Pred}_{\ne}(s)}(F_r+1000)\right),
\tag{4}
\]

不存在的前一任务项省略。同核数据前驱须已完成，合法的核心任务序保证它们位于当前任务之前。多个跨核前驱以最大释放时刻约束激活，不是把 1000 cycles 按边数累加。

对于一个生产张量，P1 在生产 Task 的输出边界形成写出，在各消费 Task 的输入边界形成读取；同一 Task 内共享输入可去重，不同 Task 则分别读取。故“把相邻操作分到同核”不足以消除 P1 跨子图通信，需要同时决定分组粒度。

### 3.4 P2：每核心一个 Task

P2 将核 \(k\) 的全部子图合并为一个 Task。同核中间数据原则上可保留，但仍可能因容量和后续操作序发生 spill。不同子图只提供核内优先级信息，不是每个子图结束后下一个子图才能启动的硬屏障；不同 Pipe 上的操作仍可能重叠。

对张量 \(t\) 的源核 \(k\) 及目标核 \(l\ne k\)，官方为对应路由插入源核 COPY_OUT 和目标核 COPY_IN。若存在多个目标核，代码按目标核生成配对搬运；不能默认一个广播写出供所有目标核免费读取。目标 COPY_IN 的释放满足

\[
S_{t,k\to l}^{\mathrm{in}}\ge F_{t,k\to l}^{\mathrm{out}}+500,
\tag{5}
\]

并仍受本核 Pipe、数据及内存约束。这里等待起点是对应 COPY_OUT 结束，不是整个源 Task 结束。原始共享输入按消费核心去重，不能使用 P1 的“每 Task/子图各读一次”规则计算 P2 的同核输入复制。

### 3.5 共享 DDR 的动态计量

DDR 总带宽固定 60 B/cycle，所有核心的相关读写共享。官方将每个 COPY 的工作量换算成独占带宽所需周期，在事件时刻按当前并发数公平分摊并重算完成时间。可将其示意为：在某时间段同时有 \(m\) 个在途 DDR 搬运时，每个搬运的参考剩余工作量以约 \(1/m\) 的速度消耗；具体整数取整、零字节最短耗时及同刻事件次序由原代码决定。

因此 \(b_t/60\) 只是独占条件下的量级，不是可以赋在所有跨核边上的固定真实通信时间。把它逐边求和也忽略了同张量路由去重、多个 Pipe 重叠和争用。本文只把这种近似用于候选生成，实际 \(T_p\) 始终读取官方输出。

### 3.6 P3：只读 FIFO Cache

P3 保留 P2 的 Task、Pipe、存储及 500 周期同步规则，增加容量 1048576 B、带宽 250 B/cycle 的共享只读 Cache。这里按官方配置使用二进制容量，不能把题面“1 MB”擅自换成 1000000 B。Cache 与 DDR 是两个独立带宽池，各自被所有核心共享；Cache 命中仍占用本核相应 MTE Pipe。

COPY_IN 在**发射时**按逻辑 tensor id 查询；命中不更新 FIFO 次序，COPY_OUT 不把数据预热到 Cache。所有符合条件的 COPY_IN 都可能查询，包括原始输入、跨核读取及相关换入；不能只统计原始图的共享输入。大于容量的单个张量不缓存。

需要精确区分描述性文档和执行代码：当前原版实现会在 COPY_IN 完成时调用插入逻辑，已经存在的 key 不重复插入。因此，一个发射时命中的读取，如果其缓存项在读取完成前被淘汰，也可能在完成时重新插入。缓存回放应按完整事件顺序，而非简化为“只有 miss 完成才可能插入”。

若张量 \(x\) 的一次实际入缓存仍未被重置，令 \(D_x\) 为此后接受插入、位于其后的其他条目的累计字节，则 FIFO 淘汰到 \(x\) 前的驻留条件可写为 \(b_x+D_x\le C_{L2}\)。该条件必须基于实际接受的插入事件：命中不刷新，已有 key 不重复插入，超大条目不插入，重新插入需重置区间。原图共享次数或静态访问距离不能直接替代 \(D_x\)。

## 4 必要下界及其适用范围

### 4.1 计算资源下界

定义 \(W_M=\sum_{v:q_v=M}d_v\)、\(W_V=\sum_{v:q_v=V}d_v\)。任一可行执行的 Makespan 满足

\[
T_p(G,\pi)\ge L_{\mathrm{resource}}(G,N)
=\max\{W_M/N,W_V/N\}.
\tag{6}
\]

**证明。**在长度为 \(T\) 的执行区间内，\(N\) 条 M 流水线最多提供 \(NT\) 周期的 M 计算容量，而原图的全部 M 操作必须执行，故 \(W_M\le NT\)。对 V 同理。两类 Pipe 可以重叠，所以取两者最大值，不能把二者直接相加。证毕。

这一结论依赖计算操作不能被本算法删除、复制后取最早结果或进一步拆分；这些变化均不在当前输出接口允许范围内。若扩展数据含其他计算 Pipe，应单独添加对应资源项，而不把它们强行归入 M/V。

### 4.2 计算路径下界

对原计算 DAG 的有向路径 \(P\)，路径内操作因因果依赖不能重叠。定义

\[
L_{\mathrm{path}}(G)=\max_{P\subseteq G_c}\sum_{v\in P}d_v,
\quad
h(v)=d_v+\max_{u\in\operatorname{pred}(v)}h(u).
\tag{7}
\]

**证明。**沿路径逐个应用完成后才能满足后继数据依赖的关系，得到末操作结束时间不小于该路径计算耗时之和。通信、同步和内存等待均非负，忽略它们只会放松约束。对全部路径取最大值即得结论。证毕。

本路径是原始计算路径，并非扩展执行图的实际关键路径。当前 `engine.loose_lower_bound` 的路径项使用原 cycles \(c_v\)，而 GraphIR 的资源项使用 \(\max(1,c_v)\)；对于零 cycles 操作，这给出更弱但仍有效的路径下界。正式表格须写清采用哪一版本，不能把两个版本的数值混在一起。式（7）给出按官方最短计算耗时加强后的理论形式。

### 4.3 必需原始 IO 下界

令 \(I_0\) 为所有必需、不同的原始输入字节总量，\(O_0\) 为原始最终输出的必需写出字节总量。对本题保证的每输入单次原始搬入、每输出单次原始搬出数据，

\[
T_p(G,\pi)\ge L_{\mathrm{IO}}(G)=\frac{I_0+O_0}{60},
\qquad p=1,2,3.
\tag{8}
\]

**证明。**P1/P2 中，每个必需输入至少从 DDR 获取一次，每个最终输出至少写回一次。P3 的 Cache 初始为空，且 COPY_OUT 不预热 Cache，故每个不同的原始输入仍至少产生一次 DDR 冷读；多核并发冷 miss 只能增加而不能减少这一必需量。最终输出仍通过 DDR 写回。任意时间区间内 DDR 服务能力至多为总带宽乘以区间长度，因此 \(I_0+O_0\le60T\)。实际 COPY 周期向上取整不会削弱该不等式。证毕。

该证明没有把内部跨核张量的首次读取加入原始输入集合，也没有假设所有调度 COPY 都走 DDR。对含重复别名、非必需输入、不同读取协议、预热 Cache 或允许删除计算的新图，必须重新确认 \(I_0,O_0\)，不能直接把任意原始 COPY 字节之和套入式（8）。

### 4.4 组合下界与整分量受限下界

三项必要约束同时成立，因此

\[
L(G,N)=\max\{L_{\mathrm{resource}},L_{\mathrm{path}},L_{\mathrm{IO}}\}
\le T_p^*(G,N)\le T_p(G,\pi).
\tag{9}
\]

三项不能相加：计算与搬运可能重叠；路径工作也已包含在计算总量中。式（9）未包含同步、容量、FIFO 与带宽时序，可能非常松。\(T_p(G,\pi)/L\) 是相对于必要界的比值；它只能给出未知最优差距的保守上界，不能据其远大于 1 就宣称存在相同幅度的可实现提升。

若额外限制每个计算弱连通分量 \(C\) 不可拆分，则还满足

\[
T_{p,\mathrm{WCC}}^*(G,N)\ge
\max\left(L(G,N),\max_C W_{C,M},\max_C W_{C,V}\right).
\tag{10}
\]

因为单个分量的全部 M 或 V 工作只能由某一个核心对应 Pipe 完成。此界用于说明整分量方法的能力限制，不能当成允许分量内部切分的全问题下界。结构审计中有 19 张多分量图的此类受限必要项显著高于基础五核资源界，这属于切分的结构动机，不是已经实现的提速。

### 4.5 不能推出的结论

本文不声称求得全局最优，也未建立近似比。相对官方单核启发式 \(B_G\) 的加速比并不普遍被 \(N\) 限制：多核输出同时改变核内顺序和 spill，而分母不是同一个最优单核问题的缩放。因此略高于核数的结果应审计，但不能仅凭该现象判错。类似地，P2 通信机制更灵活不保证固定编码在启发式调度器上一定比 P1 更快；P3 的高命中率也不保证整体时间更短。

## 5 分层候选算法

### 5.1 统一选择框架

把生成和评估分开。生成器只输出合法格式的计划及可解释 metadata，不填充“预测官方成绩”；主控对精确计划去重，按预先冻结的顺序和预算评估。只有 `success` 记录才有资格更新 incumbent，选择按式（1）进行。较好的旧方案一直保留，超时、错误和较差候选都进入记录。

```text
输入：原始图 G、核数 N、场景 p、种子和预算、公共初始计划（可选）
核验固定配置、输入和程序版本，建立 GraphIR
若提供初始计划：按当前场景正式评估并计入预算
依次生成强整分量候选，正式评估并择优
若 p=1：生成 P1 粗拓扑块；否则生成操作级列表分配候选
若 p∈{2,3} 且 profile 包含 trace：
    从当前最佳成功记录加载对应官方时间线
    生成通信、负载、优先序候选并正式评估
    只在 incumbent 更新后使用新时间线继续有限轮次
若 p=3 且 profile 包含 cache：
    回放当前最佳方案的缓存事件，生成有限缓存邻域并评估
每次完成评估后原子落盘记录、当前最佳及全部失败
预算结束或邻域停滞：输出已验证最佳计划及状态
```

此框架保证在已成功评价的有限候选集合中按目标择优，不保证覆盖所有可行方案。保留基线造成的“不退于已评价基线”是集合包含关系，不能被包装成算法创新。初始方案的评估和历史获取成本须在正式比较中统一处理。

### 5.2 强整分量对照

对每个计算弱连通分量统计 M/V 工作向量和原始输入集合。已有 simple/affinity 部分包括二维装箱、共享输入权重、有限多起点及分量移动/交换；增强组件模块复用这些已有能力，并增加 M/V 互补顺序、共享输入聚集顺序，以及每核合并、每分量一组和每核 2/4 批的中间粒度。

分量数量足够且共享输入或 M/V 比例差异满足固定结构条件时，才增加第二个种子偏移的起点；规则不读取 case 编号，也不根据已知成绩挑图。不同活跃核数都是合法候选。每个活跃核数最多保留两类有代表性的分配，再按预定质量与多样性规则选取固定前缀。

P1 代理按每 Task 的输入并集累计读量，并计同核 Task 切换；P2/P3 代理按每核输入并集计量。对计算，P1 使用同核各 Task 的 \(\max(M,V)\) 之和，P2 使用每核累计 M/V 的最大值。代理的共享 DDR 项与计算项取最大值，但它忽略 spill、真实计算依赖、MTE 和 FIFO，因此只是候选排序量，不作为官方时间或经过证明的下界。

这种对照比仅“按总 cycles 平均分”更强，也能检验内部切分是否仍有价值。然而，对于单 WCC，它仍只能使用一个活跃核；即使配置为五核也不掩饰这一限制。组件模块的候选最大数限制返回数量，不限制先构造候选池的所有工作量。

### 5.3 P1 粗粒度拓扑切块

P1 不宜直接沿用 P2 的大量操作级子图，因为每个子图都成为独立 Task，固定等待和 DDR 边界代价可能占主导。当前主控先按稳定 ID 或剩余计算路径生成合法拓扑序，再按工作量形成目标数量为 \(N,2N,4N\) 的连续块。

块分配代理保留 P1 的同核 100 与跨核 1000 周期约束，并把原始输入与跨块张量的搬运纳入粗估。候选分别采用估计最早完成核心和优先平衡可用时刻的规则。该代理并未完整模拟源端写出、共享 DDR 或核内排布，后续仍须原版 P1 评价。若粗块方案变差，组件 incumbent 保持不变。P1 与 P2 的差别在任务语义层体现，而不只是把同一候选的一个常数替换掉。

### 5.4 操作级拓扑优先序

P2/P3 当前使用四类就绪优先序：稳定 ID、剩余计算路径、静态释放倾向及带固定种子轻微扰动的释放倾向。计算尾长定义为

\[
r(v)=d_v+\max_{u\in\operatorname{succ}(v)}r(u).
\tag{11}
\]

路径优先在 Kahn 就绪集合中优先选择 \(r(v)\) 大者。释放倾向使用 \(r(v)+(B_v^{in}-B_v^{out})/60\) 排序，试图提前消费较大的内部输入并控制新产出量；它没有跟踪实际剩余引用数和驻留状态，因此不是最小内存调度。扰动只改变就绪操作之间的排名，不破坏拓扑合法性。

候选规格和次序固定，例如先覆盖两类基础顺序和不同通信权重，再加入释放倾向；当前实现至多形成 10 个分配规格和 2 个单活跃核优先块控制，重复计划去除后还可能更少。`max_candidates=20` 不会凭空产生 20 个有效方案，正式预算必须披露这种候选饱和。

### 5.5 双流水线与路由感知的核心分配

对每核 \(k\) 分别维护 \(A_{k,M},A_{k,V}\)，而非单一“核心空闲时刻”。已确定核心后，维护前驱估计结束时刻、每核外部输入读取游标，以及去重路由 \((t,k,l)\)。对尚未出现过的跨核张量路由，使用

\[
\widehat C_t=\lambda\left(500+2\max\{1,\lceil b_t/60\rceil\}\right).
\tag{12}
\]

\(\lambda\) 为代理保守程度，不改变任何官方硬件参数。外部输入按 \((t,k)\) 去重，在该核的代理读取游标上串行累加；内部扇出若复用同一已生成路由，不重复计完整传输。

对当前操作 \(v\)，候选核心的估计完成时间为

\[
\widehat F(v,k)=d_v+\max\left(A_{k,q_v},\widehat R^{input}_{v,k},
\max_{u\in\operatorname{pred}(v)}\widehat R_{u,v,k}\right).
\tag{13}
\]

若前驱同核，依赖就绪取其估计结束；跨核则取相应路由预计到达。以 \((\widehat F,\text{新增代理字节},A_{k,q_v},k)\) 按序打破并列，确定核心后才提交该选项的路由和读取游标状态。

式（12）—（13）不包含共享 DDR 动态争用、跨核 COPY 的 MTE 排队、spill 与内存复用、官方 Pipe FIFO、最终写出和 L2 事件。它们只能生成候选；不能当作通信精确模型、最优性的证书或正式成绩。去通信代价消融也须说明是否仍保留搬运字节的并列规则，避免把“权重零”误写成完全删除通信信息。

### 5.6 分配到子图编码的安全转换

给定全局拓扑序 \(\tau\) 与每个操作的核心分配，将全局序中目标核心连续相同的一段编码为一个子图；子图编号按全局位置递增，每核只列出属于自己的段。不能把某核的全部操作合并而忽略中间其他核心：例如依赖链的核心归属为 0→1→0 时，合并前后两个 0 段可能使子图收缩图出现环。

**命题。**把任意合法全局拓扑序切成连续区间，且每核按区间编号递增排列，计算依赖与同核区间顺序的并图无环。

**证明。**跨区间数据边由较早操作指向较晚操作，故区间编号严格增加；新增同核顺序边也指向更大编号。沿任一有向边编号递增，不可能回到出发区间。区间内部原计算图本身无环，命题成立。证毕。

该证明只保证所述结构条件。官方后续的内存复用和 Pipe 次序仍需完整验证。顺序控制候选有时使用单操作区间或有限长度分块，以保留可感知的优先级；仅更改 JSON 键顺序而把所有操作合成一组，不应被当作可靠的顺序控制手段。

### 5.7 时间线驱动的有限邻域

主控仅加载与当前成功计划相匹配、原始输出 SHA 核实的官方时间线。trace 生成器还检查计算操作覆盖、核心和子图归属、COPY 路由、时间及 500 周期释放关系；若换了计划，必须换用该计划的时间线，不能用旧观察迭代新方案。

当前有限邻域轮流覆盖三族，以防一个候选族耗尽预算：

| 邻域 | 实际变换 | 排序依据和限制 |
|---|---|---|
| 通信 | 生产者/消费者单操作迁移；最多 3 操作的同核无分叉短链迁移 | 读取较晚结束、释放后排队和字节数；保留同目标核全部消费者关系 |
| 负载 | 热点 Pipe 的操作移往较空核心；轻重操作交换 | 静态 Pipe 峰值变化、路由字节变化、观测结束时刻 |
| 优先序 | 固定核心分配，改变计算尾长、含跨核释放尾长或稳定 ID 顺序 | 使用原计算 DAG，跨核释放尾长仍是近似 |

晚完成 COPY 和等待时长只是候选排序特征。当前模块未重建包含全部内存复用、争用因果和 FIFO 边的执行 DAG，因此不称为“精确关键路径优化”。移动一个消费者也不一定删除整个张量路由，因为同目标核心可能还有其他消费者。

计划重编码自身可能改变优先序。若在不迁移任何操作时，重新编码已不同于原计划，须先加入独立重编码控制并评价，避免把其收益全部归为迁移。更新 incumbent 后重新加载观察；没有改进时按预定停滞规则结束，而非无限追加搜索。

### 5.8 缓存事件邻域

Cache 模块将官方访问分类为 hit、首次访问 miss、首次插入完成前的并发冷 miss、淘汰后 miss 和超容量 miss。回放 FIFO 队列验证事件顺序、占用、淘汰对象、最终条目及聚合字节命中率，避免仅靠汇总命中率猜测原因。

候选目标优先选择重复读取中可能影响后续计算尾部的 miss。当前关键性代理由原计算依赖和同 Pipe 观测尾部构成，未涵盖完整内存/DDR 因果，因此只作为目标排序。主要变换是提前已有读取者及其必要祖先、在后续读者之前安排已有独立计算、提前淘汰后才读取的消费者，或将小规模消费者集合迁移到较早读取的核心。算法不插入题目未允许的预取操作、空转操作或额外等待指令。

Cache 候选先包含“保持分核、按观测计算顺序重新编码”的控制。若控制已改善时间，只能认定顺序表达有效，不能把全部改善归为缓存专项动作。命中率增加、miss 字节减少和 Makespan 改善分别统计；接受条件仍是官方目标值。

### 5.9 复杂度与停止条件

建图和弱连通分量提取可线性扫描节点与边。拓扑优先序使用就绪堆，主要成本约为 \(O((|V_c|+|E_c|)\log|V_c|)\)。一次列表分配需遍历候选核心及相关前驱/输入关联，规模随 \(N\) 和张量关联数增长；本题 \(N\le5\)。真实总开销还包含计划构造、结构校验、重复候选哈希以及官方编译模拟。

组件模块对有限多起点做有界移动/交换；trace/cache 只返回受限邻域，但候选生成过程仍会扫描图、时间线和祖先集合，最坏情况下不能宣称常数时间或整体线性。由于当前生成器可能先生成池再截断，候选上限不是生成时间上限。

主控采用两层停止条件：逻辑评估次数限制和协作式剩余时间；正式硬墙钟实验还由外层独立进程监督，将图解析、生成、评估和 checkpoint 写入纳入同一时限，超时终止整个子进程组。只从已经成功评估且校验通过的 checkpoint 恢复方案。没有可行输出、预算超时但有可行 incumbent、以及完整结束是不同状态。

## 6 实验设计与归因原则

### 6.1 研究问题与预设比较

正式实验围绕以下问题：强整分量对照之外，内部切分能否在相同预算上限下改善时间；M/V、通信和顺序代理分别贡献多少；时间线反馈是否超越纯静态候选；Cache 条件下的策略改变是否优于仅开启硬件；这些收益的搬运、失败率和求解成本如何。

当前存在历史探索批次和依据正式协议 v2 新启动的批次，二者不能合并成一个“同预算实验”。历史批次允许用于机制分析及代码核验；正式比较另建独立输出目录，在运行前冻结候选顺序、阶段配额、种子、每次 timeout、图规模预算规则和失败处理。v2 已冻结不代表其完整结果已经产生。

| 比较/消融 | 保持相同的条件 | 检验对象 |
|---|---|---|
| simple、affinity、增强 component | 原图、场景、核数、总预算规则 | 二维负载、共享输入及粒度效果 |
| component → operation/coarse-P1 | 公共初始方案及总预算 | 打开内部并行与场景适配 |
| 操作级去通信代理 | 顺序族、候选数量规则和预算 | 同步/路由估计的贡献 |
| 相同核心分配、不同顺序 | 核分配及场景 | 纯顺序/重编码作用 |
| operation → trace | 总预算及公共初始信息 | 正式反馈和邻域选择 |
| P3 通用候选 → cache 邻域 | L2 配置、总预算、重编码控制 | 缓存特定变换的额外贡献 |

若一个方法的候选天然少于预算，应报告实际使用次数和饱和停止，不能重复评价同一计划凑数；同上限不等于同实际消耗。若某 ablation 需要新增规格或变换，须在正式运行前实现、冻结并测试，不能把尚未执行的消融写成已完成。

### 6.2 等预算的两个独立维度

**逻辑调用上限。**计费单位是一次新的精确方案、场景和核数的评价请求。包括成功、超时和评估失败；同一算法内部精确重复去重不重复计费。成功缓存命中仍占逻辑调用名额，并另列真实子进程调用及缓存命中数，防止后运行方法因复用结果而得到更多搜索机会。正式 v2 不注入历史最好方案，各方法从同一生成器的首个整分量计划开始，这一首次评价包括在 Component 配额中。

| v2 场景/方法 | Component | Operation/P1 粗块 | Trace | Cache | 总逻辑上限 |
|---|---:|---:|---:|---:|---:|
| P1 Component | 12 | 0 | 0 | 0 | 12 |
| P1 联合 | 4 | 8 | 0 | 0 | 12 |
| P2/P3 Component | 24 | 0 | 0 | 0 | 24 |
| P2/P3 Operation | 4 | 20 | 0 | 0 | 24 |
| P2/P3 Trace | 4 | 8 | 12 | 0 | 24 |
| P3 全方法 | 4 | 8 | 8 | 4 | 24 |

P2 全方法对应 Trace 行。各阶段最多三轮迭代、每轮最多 12 候选，未改善则按停滞规则结束；阶段余量不临时挪用。Operation 固定池至多 12 个唯一方案，所以该 profile 可能在总计 16 次以内饱和。比较的是相同上限，须同步展示实际用量及从原顺序选择轨迹提取的 4/12/24 次预算曲线，不将曲线事后按得分重排。

**端到端硬墙钟。**用独立空缓存、相同机器和相同任务并发度，从启动子进程开始计时，包含读图、生成、验证、正式模拟和交付落盘；公共官方单核参照计算单独列示。外层监督器到时终止整个进程组，回收已落盘的可行 incumbent。恢复校验及最终导出耗时另行报告，若它们超过预算必须披露，不把子进程计时冒充整个用户请求耗时。

预算不得按 case 编号或预期提升临时调整。v2 以原始非 COPY 操作数设单次正式评价 timeout：不超过 10000 个为 60 秒，超过为 180 秒。总调用配额已包含首次 Component 评价，不额外赠送优化起点。主种子为 17；机制验证集固定为 011/019/044/049/051/064/069/071/082/093，并明确包含开发图。

撰写本版时，v2 的 P1/P2 联合方案各 400 个槽（100 图×2—5 核）已启动，workers=3，尚无完整全量成绩。该设置是调用预算批次，复用精确成功缓存仍按逻辑请求计费，不冒充冷缓存墙钟实验。P3、组件/其他 profile 对照与独立墙钟实验须按各自完整记录报告，不能从启动状态推定完成。

### 6.3 P1/P2 加速比及聚合

对图 \(g\)、核数 \(k\)，

\[
S_{p,g,k}=\frac{B_g}{T_p(g,\pi_{p,g,k})},\qquad p=1,2.
\tag{14}
\]

\(B_g\) 必须由原版 `singlecore_evaluate.py` 的整图单核流程获得，不能替换为优化后的单活跃核计划或某个 WCC 基线。主曲线 \(k=1\) 按题面规定为 1；改进过的单活跃核时间可另表给出。本文约定“平均”为逐图比值的算术平均：

\[
\overline S_{p,k}=\frac1{100}\sum_{g=1}^{100}S_{p,g,k}.
\tag{15}
\]

题面未进一步指定加权聚合，因此显式说明该约定。它不是 \(\sum_gB_g/\sum_gT_g\)。除主均值外报告中位数、差分布、逐图胜/平/负、覆盖和求解成本，保留所有逐图分子分母。

### 6.4 P3 四格归因

对同一张图、同一核数，先由预先定义的 P2 和 P3 搜索分别得到 \(\pi_2\)、\(\pi_3\)，再补齐：

| 方案 | 无 L2（P2） | 只读 Cache（P3） |
|---|---:|---:|
| P2 选择的 \(\pi_2\) | \(T_2(\pi_2)\) | \(T_3(\pi_2)\) |
| P3 选择的 \(\pi_3\) | \(T_2(\pi_3)\) | \(T_3(\pi_3)\) |

定义同方案硬件收益 \(H\)、P3 条件下策略收益 \(Q\) 及总收益 \(R\)：

\[
H=\frac{T_2(\pi_2)}{T_3(\pi_2)},\quad
Q=\frac{T_3(\pi_2)}{T_3(\pi_3)},\quad
R=\frac{T_2(\pi_2)}{T_3(\pi_3)}=H Q.
\tag{16}
\]

乘积等式只逐图成立，\(\overline H\,\overline Q\) 不等于 \(\overline R\)。第四格 \(T_2(\pi_3)\) 检查新策略是否在无缓存条件下也改进：如果是，收益可能来自一般顺序/负载变化，不能独占归因于缓存。若需考察相对适配，可附加比值比 \((T_2(\pi_3)/T_3(\pi_3))/H\)，但它仍是交互诊断，不是不存在调度相互作用的因果证明。

交叉评估只用于冻结方案后的归因，不将免费结果反馈继续搜索。配对中任一格失败或缺失，该四格不完整，不能进入完整配对均值；须明确显示 0/N 或成功数量，不能删除整张图后冒充全量。P3 的单核收益按真实同核数比值计算，不强制为 1。

### 6.5 搬运、命中率和失败

官方额外搬运为调度后静态 COPY 字节减原始 COPY 字节。P3 命中不会使该字段自动扣除命中字节，故同时报告官方静态搬运及 Cache 动态访问指标。字节命中率是 `hit_bytes/(hit_bytes+miss_bytes)`，不是访问次数命中率；`miss_bytes` 只统计相应 COPY_IN 未命中读取，不等于全部 DDR 读写量。

每个预定配置报告 expected/success/timeout/invalid/runtime-error/generation-error/no-feasible/fallback 数量。超时表示在时间内没有完成评价，不代表计划被证明非法。如果有预先规定且已评价的回退计划，则其真实成绩可进入最终输出，同时标注回退；不存在已验证方案时不得填入猜测时间。含缺失的分组不报“全 100 图平均”。

### 6.6 随机性、开发集及统计解释

确定性方法不重复同一输出制造标准差。涉及随机种子时预先固定 17、29、43，报告逐种子结果及中位数/范围，明确先逐图聚合还是先按种子聚合。建议主表按每个种子的全图均值并列，附表给逐图三种子中位数，从而避免把不同聚合顺序混用。

已用于结构探针、组件、trace、cache 调试的案例均属开发案例，清单从各 manifest 汇总，不能只披露最早四张图而把后续调试图称为未见样本。100 图为题目给定有限用例集；全量结果可以描述该集合，但若没有独立新图验证，不应宣称对任意神经网络图的统计泛化。总体固定数据集比较优先报告效应量和分布，而不依靠选择性 p 值制造确定性。

## 8 可复现性和交付设计

### 8.1 输入、程序和运行身份

每个运行 manifest 记录原图与配置路径及 SHA256、全部原官方 `.py`、wrapper/worker、候选生成器及依赖脚本 SHA、Python 版本与可执行文件、平台、场景、核数、种子、候选及时间预算、命令、公共初始计划 SHA 和版本。源码快照独立保存，批次运行期间不更改冻结文件。仅记录入口文件哈希不足以识别实际运行代码。

正式100图输入哈希基准为 `方案审阅/结构核验/a_structure_summary.json` 的 `input_sha256`；官方配置及 10 个 Python 文件的原始基准为 `方案审阅/cache_microtests/provenance.json`。已有独立复核在评估前后确认原配置与源码未变。未来正式批次仍须重复该核验，不能用过去一次哈希检查替代当前状态。

### 8.2 精确计划缓存及顺序

结果缓存绑定原图、场景、固定配置、全部官方源码、wrapper/worker、Python 运行身份及精确计划内容。不能只用 case、核数、方法名或无序 JSON 内容作为复用键。当前实现对 `node_to_subgraph` 的插入顺序采取保守保留，因为官方构造过程可能读取该顺序；即使数学上看似同一划分，也不擅自证明其等价。列表顺序更是明确的决策变量。

复用成功记录时校验原始压缩输出 SHA，加载结果与记录的 Makespan 一致；方案与 record 的 `plan_sha256` 对应。缓存命中与真实官方进程调用分开记录。精确缓存用于避免重复成本，而不产生额外预算或取代独立空缓存重评。

### 8.3 每次尝试的账本

每次候选保存计划、请求、attempt_id、开始/结束时间、status、timeout、stdout/stderr、退出码、峰值内存（若可得）、官方原始输出及其 SHA、计分摘要、来源和父 incumbent。候选未评价须说明原因，生成错误也单独记录。超时记录保留，不以成功重跑覆盖原失败。当前主控在一次 evaluate 返回后才将其计入 checkpoint；若外层硬杀发生于评价途中，最后一个已发起请求可能未计入汇总。因此硬墙钟实验需另外核对 `evaluations/attempts` 中未完成的 request，将其标为 interrupted，不能把 checkpoint 中已返回次数当作所有已发起调用数。此项不影响旧成功 incumbent 的真实性，但影响完整成本账本。

历史大型单核恢复说明这种区分必要：072、076、091 在原时限下超时，经独立目录、同官方 p0、1200 秒上限重算后，真实单核时间分别为 23897828、6185113、9186769 cycles。恢复的是相同定义的官方基准，未用启发式单活跃核替代；原失败仍留在历史证据中。恢复记录分别位于 `实验记录/large_baseline_recovery/` 与 `large_baseline_recovery_091/`。

### 8.4 中断恢复的语义

当前入口在新运行目录工作，拒绝覆盖旧证据。主控每次成功或失败尝试后原子写 checkpoint；外层监督器在预算截止时终止求解及其官方 worker 进程组。恢复仅认可状态 success、计划哈希正确、原始输出未变且输入/源码一致的已完成记录。

“成功交付可行计划”与“搜索完整完成”分别记录：有可行 incumbent 的超时运行可以交付已验证结果，但标记 `completed=false` 和预算停止原因；没有可行方案不能仅因进程正常退出就记 success。恢复期的重新校验及导出秒数应与子进程硬预算分别披露。若代码更新导致来源哈希变化，应另建新批次而不是静默覆盖。

### 8.5 独立复核与测试范围

单元测试用于核验不会被普通运行轻易发现的语义，例如 Task 与核心输入复制口径、M/V 资源计算、拓扑编码、参数范围、失败不替换最佳、缓存命中仍计逻辑调用、旧时间线拒绝和恢复计划哈希。通过单元测试不能替代实际官方评估。

独立复核从原图和已冻结计划出发，在空缓存目录用原 wrapper 重评代表性高提升、异常高加速、退化和大图；比较最终官方时间、搬运、活跃核心、缓存事件及哈希。已有四图操作级和单操作移动记录具备此类证据。正式全量完成后应按预先规则抽取极端值复核，不能只选择成功或好看的案例。

### 8.6 交付包结构

提交包应包含源代码及依赖说明、官方输入/代码哈希清单、冻结命令和协议、各问题及核数的计划、逐图指标 CSV、完整状态索引，以及足以复现论文主表和图的汇总脚本。官方附件本身不改写。历史探索、正式公平比较与最终汇总的最佳计划分目录存储，避免读者把不同预算或不同计划的同名指标混在一起。

## 9 局限、敏感性和后续验证

代理没有完整表示 DDR/MTE、存储复用和 FIFO，因此可能选出严重退化候选，当前依靠正式评价筛除。理论下界忽略这些约束，不能作为接近最优的充分证据。trace 的“较晚/等待/尾部”不是完整执行关键路径，cache 的排序也不是准确的反事实时间预测。

当前正向探索集中于若干开发图；强组件候选的有限探针也未显示普遍收益。完整 1—5 核、P3 四格和统一预算实验尚需补齐。本文保留这些边界，因为它们决定最终结论能否从“有几个好例子”提升为“对规定集合稳定有效”。

题目固定配置下的正式成绩不得通过修改硬件参数提高。若另做容量或带宽敏感性研究，必须独立标为补充分析并保留原配置主表；不能将新配置模拟混入正式加速比。当前未完成此类实验，本文不填写相应曲线或定量结论。

后续工作的优先顺序是：冻结正式协议并完成相同预算上限比较；补齐 P3 四格与负例；以结构分组解释改善和退化；随后再考虑更准确的执行因果模型或容量感知代理。每项新复杂机制都应通过对应消融证明有用，而非通过名称或模型规模制造创新感。

## 10 结论

本研究将赛题处理为由固定核内编译与离散事件模拟共同决定目标值的组合决策问题。正确区分 P1 的 Task 边界、P2 的核心 Task 合并和 P3 的动态只读缓存，是建立有效调度方法的前提。必要下界解释资源和依赖限制；场景相关的分层候选提供可执行搜索空间；正式评估、incumbent 保留和完整账本使正负结果都可核验。

已有实验确认了整分量方法的局限、操作级分配在部分困难图上的潜力，以及顺序、通信和缓存收益之间的非单调关系。全量 P2 五核探索也明确揭示：新操作候选单独使用时在 51 张图上退化，不能替代全部组件方案。历史 WCC 与新候选的联合保留提供更好的已验证交付集合；这一互补收益在统一预算和全部核数上能否持续，仍须由待完成的正式实验回答。
