# P3 关键读取缓存局部改进

`cache_refine.py` 是候选生成器，只读原图、原方案和已经成功的 **完整 P3 官方结果**。它不调用评估器、不改硬件参数，不注入等待、预取或额外操作。由外层控制器用官方 makespan 选择方案，始终保留传入的成功方案。

```python
from cache_refine import generate_cache_candidates

candidates, diagnostics = generate_cache_candidates(
    ir, plan, official_result,
    num_cores=5, max_candidates=12, round_index=0, seed=0,
)
# candidates: [{"name": str, "plan": 官方双字段方案, "metadata": dict}, ...]
# diagnostics: 可 JSON 序列化的机制核验、读取分类与排序依据
```

`ir` 是现有 `solver.graph_ir.GraphIR`，`official_result` 应解压 evaluator record 的 `result_path`，不能传 wrapper record 本身。支持配置核数 1–5，允许空核；`max_candidates` 包含第一个重编码控制；相同输入、seed、round 产生相同结果。原输入均不修改。不一致的观察抛出 `CacheResultMismatch`（`ValueError` 子类）；参数错误抛出 `ValueError`。全程仅用标准库。

## 先核验观察，后生成候选

- 原计算 op 精确覆盖一次，核与 SG 符合原方案，op 类型、Pipe、周期及原依赖符合原图。
- 核对官方固定配置：DDR 60、缓存 1 MiB/250、跨核释放延迟 500、L1 512 KiB、UB 128 KiB。配置不合则拒绝。
- `cache_events` 用 `(core_id, op_id)` 关联 COPY_IN；逻辑 tensor ID 与字节数必须在原图中匹配。不能把 COPY 的优先级 SG 当成实际消费者，也不能把根 DDR tensor ID 与本地逻辑 tensor ID 混用。
- 依官方事件原顺序重放 FIFO，包括同周期“先完成并插入、后发射读取”。命中不刷新队列；核对逐次淘汰、占用、最终 FIFO 顺序与累计命中/字节统计。
- 跨核传输必须精确对应原 tensor 的生产者核到消费者核的路由集合，COPY_OUT/IN 的时刻互相一致，且读取释放时刻严格等于写出完成 +500。命中也不能删除这 500 周期。
- 原始官方结果不包含足够的加密来源信息。外层仍须验证 evaluator record 的 graph/plan/config/code 哈希与 gzip 文件完整性；这些内部一致性检查不能替代来源绑定。

读取分为首次 miss、首次插入前重叠读取的并发冷 miss、曾插入后被淘汰再读的 miss、超容量 miss 和 hit。对 hit 另外报告“发生在非末端核且计算尾链有余量”的代理诊断，不能据此证明它完全不影响其他核的 DDR 争用。

## 关键性只是可检查的代理量

在观察到的计算时间线上，结合原依赖与同核同计算 Pipe 的顺序，计算每个 op 的剩余计算尾链。对每次读取，映射本核中尚未开始的原 tensor 消费者，使用尾链长度、距离全局结束的时间、读取结束到消费者开始的间隙排序。

读取收益代理是 `实际 COPY 时长 − ceil(字节数 / 250)` 的非负部分。它忽略后续带宽争用、释放延迟和内存依赖变化，不能当成可实现的节省。官方公开结果没有完整的内存复用/排队因果图，因此本模块不声称恢复了精确关键路径，也不将命中率作为优化目标。

## 候选及控制

1. **观察顺序重编码控制**：保持 op→core，将当前观察到的全局计算拓扑序编码为每个原 op 一个 SG。同核相邻 op 不能简单合并，否则 SG 内的原规则会抹掉想表达的优先序。控制本身可能改变性能，收益必须单列。
2. 提前已经存在的 leader 读取消费者及必要祖先，让其他核有机会在其首次读取完成后命中。
3. 将 follower 核上已有、与目标 tensor 消费者没有祖先依赖的短工作前置。仍须官方检验有用工作是否足以覆盖首次读取时间，以及错峰代价是否抵消收益。
4. 对淘汰后复读，尝试提前复用消费者及必要祖先，缩短两次复用间的插入量。
5. 少量消费者共核。至多移 4 个本核消费者；较大集合只移关键消费者，并明确记录剩余路由可能仍存在。不能假设共核必然改善负载或消除全部搬运。

每个候选先通过原依赖的 Kahn 拓扑排序，再以单 op 区间及递增同核 SG 顺序编码，最后调用 `validate_plan`。这保证计算覆盖和结构无环，不保证官方加入 Pipe/内存复用/搬运依赖后一定可执行。失败、超时或不改善者由主控保留记录并拒绝替换 incumbent。

`round_index` 只改变有限的局部前移窗口和目标轮转；模块没有按题号分支。多轮观察顺序控制不是恒等变换，迭代所得改善应归属于“观察反馈与局部调度”的整体过程，不能全算缓存定向搜索贡献。
