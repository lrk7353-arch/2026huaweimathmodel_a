# 强整分量对照候选模块

实现文件：`component_baseline.py`。本模块是用于公平比较和初始可行方案的整WCC参考方法，不把候选组合包装成已经取得提升的新算法。它不拆分计算依赖弱连通分量、不调用官方模拟器、不读取历史成绩或用例编号。

## 接口

在Python模块搜索路径中加入`A题研究`后：

```python
from solver.graph_ir import GraphIR
from advanced_solver.component_baseline import generate_component_candidates

ir = GraphIR.from_path(graph_path)
candidates, diagnostics = generate_component_candidates(
    ir, num_cores=5, max_candidates=12, seed=17
)
```

每个候选恰有`name`、`plan`、`metadata`三项。`plan`严格使用官方两个字段，N条core_schedules保留空核。核数范围1—5，`max_candidates`是返回候选数量上限；它不是生成过程的严格时间上限。相同图和seed输出确定，较小候选上限是较大上限的固定前缀。

可以分别用P1/P2/P3官方评估器评价同一候选池。函数没有problem参数，因此不做利用某场景实测成绩的隐式筛选；场景差异通过下述两套代理披露，最终必须由该场景官方Makespan选择方案。

## 实际组成与新增部分

1. 复用现有`solver.baselines`的simple/affinity生成器。它执行M/V二维装箱、共享输入感知选择、两个权重和两个初始顺序、有限分量移动/交换。不能把这部分已有工作重新命名为新的贡献。
2. 只有当分量数量足够，且存在共享root输入或分量M/V工作比例范围不小于0.35时，增加第二个固定种子偏移104729的候选生成调用。随机变化只由显式seed控制。
3. 对每个可用活跃核数，最多选两个不同的整分量到核分配：低计算/DDR代理成本者，以及低root输入复制量者。然后构造新的Task粒度与顺序候选。
4. 新顺序包括M/V互补编排，以及按高共享价值root输入聚集分量。新中间粒度将每核分量按工作量连续分为2或4批；同时保留每核一个子图、每分量一个子图。这些变化可减少P1重复输入与Task切换之间的极端选择，并为P2/P3提供不同的核内优先序。这里不承诺它们比两种端点粒度更快。
5. 精确去重保留JSON映射插入顺序，避免将未证明等价的构造顺序当作同一官方输入。纯sg编号或核编号对称性没有被强行合并。

## 两套代理及口径

| 计量 | P1代理 | P2/P3代理 |
|---|---|---|
| 原始root输入读取 | 每个Task的root输入集合各读一次 | 每个核心的root输入集合各读一次 |
| root输入复制 | 上述读取总量减全图唯一root字节数 | 同左，但使用每核读取总量 |
| M/V计算 | 每Task的max(M,V,Other)按同核Task相加 | 每核的max(总M,总V,总Other) |
| 同核Task切换 | 每相邻Task计100 cycles | 无该项 |
| DDR项 | `(Task读取量+原始最终输出量)/60` | `(Core读取量+原始最终输出量)/60` |

代理取计算项与共享DDR项的较大者。`Other`只作防止遗失工作量的补充维度；正式100图的非COPY操作以M/V为主。代理既不等于官方Makespan，也不是经过证明的下界。它不建模spill、张量生存期、动态带宽争用、准确计算/搬运重叠、Pipe FIFO与L2命中/淘汰时序。

`component_proxy(ir, plan)`也可独立调用以查看上述信息；它拒绝将拆开WCC的方案冒充整分量方案。官方L1/UB可执行性和最终全局依赖仍须评估器检查。

## 固定排序与调用预算

在可用时依次保留：最大活跃核M/V LPT、原始整图单活跃核形状、中间Task粒度对照、每分量一个子图对照。剩余名额使用归一化P1/P2联合代理，以及分核映射、活跃核数、粒度和顺序四类多样性惩罚。系数在代码中固定，不按图编号或已知成绩调整。

选择不仅看“有没有共享输入”：每Task与每核分别去重，保证P1的复制开销不会错误使用P2的读取量。各候选metadata保存两套计量、原始来源、多起点信息及选择理由；diagnostics保存结构触发条件、完整池大小与返回候选覆盖。

前缀含公共参考形状不意味着其分数已经免费获得。正式比较时应统一规定公共初始方案的获取和计费方式，生成器只交付计划，不提供被评估的incumbent。也不能把“候选池包含基础LPT，择优后不会比已评估的LPT差”写成独立的算法优势证据。

## 复杂度与边界

最多调用两次legacy候选生成。legacy每个初始解的局部搜索至多两轮64个分量的移动及两轮96对交换。Task布局最多展开每个活跃核数的两个分配、两个顺序、三个粒度。每个布局包含分量排序、输入集合合并及计划构造/结构校验，成本约为`O(C log C + I + V + E)`；C为分量数、I为分量-root输入关联数。完整选择的保守上界为`O(K × P × C)`，K为候选上限、P为生成池规模。

输入图上的一个巨大WCC在本模块中仍不能拆开；这是对照方法的明确能力边界。最大核数并不要求全部核必须活跃，少核方案是合法候选。所有返回方案的官方合法性与分数仍须实测，任何失败都应保留。

## 验证

12项单测覆盖：P1/P2读取口径区别、M/V互补与Task切换、拒绝WCC拆分、精确覆盖、确定性和不修改输入、改路径不改答案、不同候选上限前缀一致、结构触发、单WCC与空图边界、参数校验。

```sh
python -B -m unittest discover -s A题研究/advanced_solver/tests -p test_component_baseline.py -v
```

另按预设001/011/044/049/069/071、5核、P1/P2、每槽前4候选进行单worker真实评估，每次60秒，最多36调用。单WCC去重后自然只剩一个方案；不为凑调用数重复运行。运行清单、全部成功/失败/退化记录见`runs/component_probe_v1`。这是小规模接口与行为核验，不是全100图或相同墙钟预算下的性能结论。

该固定探针已完成36次，全部成功、无缓存复用。只有011/P2相对首个LPT改善约0.79%；其他最佳持平，多个中间粒度P1候选反而变慢。049在本次4候选前缀下也略慢于历史不同预算组合。完整正负结果见[实测说明](runs/component_probe_v1/README.md)，不据此宣称任何通用性能优势。
