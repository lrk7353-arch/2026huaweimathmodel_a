# A题100图独立结构核验

本次独立读取原始 `case_001.json` 至 `case_100.json`，未导入、执行或修改官方评估器，也未修改原图。结果为静态数据统计，不是性能复现实验。原文件SHA-256记录在 `a_structure_summary.json`。

复现命令（工作目录为项目根目录）：

```bash
python3 A题研究/方案审阅/a_structure_audit.py --data 选题分析/A题附件/data --output A题研究/方案审阅/结构核验
```

## 定义

- 计算节点：`op` 不等于 `COPY_IN` 或 `COPY_OUT` 的操作。全部100图的计算节点都位于 `PIPE_M` 或 `PIPE_V`。
- 计算依赖：由张量的生产者指向消费者。若中间经过COPY节点，继续追踪到最近的非COPY后继。只共享输入的两个消费者之间不添加计算依赖。本数据中收缩COPY没有产生直接计算依赖之外的额外边，但脚本仍显式实现了收缩。
- 计算分量：上述计算DAG忽略边方向后的弱连通分量。
- 共触达分量：对每个L1/UB张量，将所有接触它的非COPY生产者和消费者连在一起。这是用于核对另一种原子块定义的对照，不能与计算分量混用。
- 原始DDR输入：没有生产者、由原始COPY_IN读入的DDR张量。沿COPY追踪到最近计算消费者，以消费者所在计算分量判定是否跨分量共享。全部100图均满足每个这类输入只COPY_IN一次，且唯一DDR输入字节之和等于按COPY_IN输出统计的搬入总字节。
- 层数：最长计算依赖链的节点数。同层宽度不是严格的最大反链宽度。关键路径仅计计算周期，不计搬运、同步和spill。

## 需要防止的过度推论

1. **84图有多个分量，不等于84图只需整体装箱。** 其中13图最大计算分量仍超过全部计算节点的50%，4图超过90%（case_003、case_049、case_054、case_056）。所有100图中，最大分量占比中位数为12.2024%，但极端大块必须单独处理。
2. 计算分量数分布为：1个16图，2–4个0图，5–19个11图，20–99个46图，100–999个24图，1000个以上3图。分量数量足够不等于分量工作量均衡；case_056的最大计算分量约占97.21%的节点、96.02%的PIPE_M工作量。
3. 若强制整个计算分量留在单核，额外有下界 `max(最大分量M工作量, 最大分量V工作量)`。在84个多分量图中，有19图加入该限制后的5核下界至少是简单原图下界的1.5倍。这是结构诊断，不是实测损失倍数，也不是最优性差距。
4. 五核粗下界 `max(W_M/5, W_V/5, 原始COPY总字节/60, 计算关键路径)` 的最大项确为68图PIPE_M、27图PIPE_V、3图关键路径、2图原始DDR。它只比较原图下界项，不能证明95图最终模拟运行都为计算瓶颈；切分复制、spill、FIFO阻塞和同步均未进入这项分类。
5. 原始输入总量能装进L2，不保证实际时序能命中。是否有复用、首次搬运完成时刻、其他可缓存读入和spill、FIFO淘汰都需另核实。

## 产物

- `a_graph_structure.csv`：逐图规模、分量、层级、Pipe工作量、原始输入、共享输入、关键路径与下界诊断。
