# 三、我们之前对第一份售卖方案的批评，被正式数据验证了

那份方案把：

> “通过 L1/UB Tensor 联系起来的 Op”

直接作为不可拆的“原子单元”。

我之前就怀疑这样定义会有问题。

正式数据统计以后发现：

### 按它那种“Tensor 共触达”定义：

- **44 / 100** 个 case 直接变成一个大连通块；
- **53 / 100** 的最大块占全部计算 Op 的 90% 以上；
- 最关键的是：

> **没有任何一个 DDR 共享输入跨越这种原子块。**

也就是：

```text
所谓“原子单元”
+
“单元之间共享输入超边”
```

在它自己的定义下，后面的共享输入超图几乎被自己消灭了。

所以我们上一轮指出的逻辑漏洞是成立的。

## 但它的优秀思想可以救回来

只需要把“原子单元”改成：

> **非 COPY producer→consumer DAG 的弱连通分量**

- 84 个 case 有多个独立单元；

- 于是共享输入超图真的出现了。

因此正确结构是：

```text
Dependency Components
        ↓
共享 DDR 输入形成 Hyperedge
        ↓
多维超图划分 / 装箱
```

这就非常漂亮了。

# 七、现在我认为三问应该完全分开建模

这是我们最终框架的核心。

---

# 问题一：Task-aware DAG / Hypergraph Partition

P1 最核心的特殊规则是：

> 一个 Subgraph 就是一个 Task。

不同 Task 即使在同一个 Core：

> **缓存也全部清空。**

跨 Task 数据必须走 DDR。fileciteturn0file0L110-L115

所以 P1 真正优化的是：

\[
\boxed{
\text{切图粒度}
+
\text{核分配}
+
\text{Task 顺序}
}
\]

---

## 第一类 case：大量独立 dependency components

这是 100 个 case 的主体。

建立：

### Vertex

每个独立计算分量 \(C_i\)。

权重：

\[
w_i=
(W_i^M,W_i^V,M_i^{L1},M_i^{UB})
\]

### Hyperedge

若多个分量共享一个 DDR 输入 \(t\)：

\[
h_t=\{C_i:t\text{ 被 }C_i\text{ 使用}\}
\]

权重：

\[
s_t
\]

如果该输入被分散到 \(r_t\) 个 Task：

\[
Traffic_t=(r_t-1)s_t
\]

---

然后目标就是：

\[
\min
\left[
\max_k W^M_k,
\max_k W^V_k,
B_{extra},
TaskPenalty
\right]
\]

求解：

> 多级粗化 + 多维 LPT + FM/KL 局部优化。

这里网上第一份方案的思想可以真正发挥作用。

---

## 而且很多这种 case 可以直接尝试：

\[
K=N
\]

也就是：

> 一个 Core 一个大 Subgraph。

因为独立 component 可以自由合并。

这时：

- 同核无需 Task 切换；
- component 内无额外边界；
- 强共享输入 component 可以合并；
- 核间没有 dependency wait；
- 只剩负载均衡。

这解释了为什么刚才 case001 能做到：

\[
4.907\times
\]

所以第二个视频博主说的：

> `K ≈ N`

**并不是完全错误。**

正确说法应该是：

> 对“独立 component 丰富”的图，K=N 极可能是非常强的方案；但不能推广到所有图。

# 八、P1 真正难的是剩下那一小批“大连通 DAG”

正式数据里只有 16 个 case 是纯单连通，约 20 个是一个大块占绝对主体。

这些才是 P1 真正值得研究的部分。

比如有的：

```text
17995 Op
2440 层
每层宽度约 12
```

有的则是：

```text
19636 Op
仅约 28 层
最大一层 2181 个 Op
```

两者显然不能使用同一种切法。

---

我建议这里做第二层结构分解：

### ① Critical Path

求：

\[
rank_f(v),\quad rank_b(v)
\]

定义：

\[
slack(v)=CP-rank_f(v)-rank_b(v)
\]

避免在高 criticality 区域产生高成本跨核切分。

这个就是第二个视频做得好的地方。

---

### ② Fork-Join / Parallel Region 检测

识别：

```text
       ┌ Branch A ┐
Fork ──┼ Branch B ┼── Join
       └ Branch C ┘
```

这种地方才是真正应该多核展开的地方。

可以采用：

- dominator / post-dominator；
- forward/backward depth；
- frontier；
- 小割集；
- DAG separator。

---

### ③ DAG-convex partition

这里有一个非常容易踩的坑：

> 随便把 DAG 里的节点 merge，会让“子图 DAG”产生环。

我刚才做原型时甚至亲手触发了一次官方：

```text
contracted subgraph graph contains a cycle
```

所以最终算法必须明确加入：

# **Acyclic contraction constraint**

也就是每次：

```text
merge / move / split
```

都必须保证 quotient graph 仍是 DAG。

这是一个很好的论文建模点。

# 十一、P2 我会采用“HEFT + Hypergraph FM”两层求解

### 第一层：Communication-aware HEFT

按照 upward rank：

\[
rank_u(v)
=
w(v)+
\max_{u\in succ(v)}
(c(v,u)+rank_u(u))
\]

然后每个 Op 选择使 Estimated Finish Time 最小的 Core：

\[
core^*(v)=
\arg\min_k EFT(v,k)
\]

这里 EFT 同时考虑：

- PIPE_M / PIPE_V 当前负载；
- predecessor finish；
- 500 cycles；
- Tensor 搬运；
- 共享输入复制。

---

### 第二层：FM / Local refinement

允许：

```text
move(v, coreA → coreB)
swap(v,u)
move(branch)
```

delta score 同时计算：

- Compute imbalance；
- Input replication；
- Cross-core intermediate traffic；
- Critical path；
- spill risk。

# 十三、问题三现在我认为反而有一个很漂亮的创新点

- miss → DDR；
- **miss 完成后才写 Cache**；
- hit → 独立 250 B/cycle Cache 带宽；
- FIFO；
- hit 不刷新 FIFO。fileciteturn0file0L400-L408

## 我对正式数据又做了统计

所有原始输入 Tensor：

> **没有任何一个单 Tensor 大于 1 MB。**

最大单个大约：

\[
295KB
\]

所以全部都可缓存。

而且：

> **50 / 100 个 case 的全部原始 COPY_IN 总量本身都不超过 1 MB。**

也就是说 P3 并不是一个装饰性问题。

L2 在相当多 case 里理论上有非常强的发挥空间。

# 十四、P3 的真正创新：Leader–Follower Cache Scheduling

网上第一份方案的问题是：

> 让多个 Core 同波次读取同一个 Tensor。

但这会：

```text
Core0 发 COPY_IN(X) → miss
Core1 同时发 COPY_IN(X) → 还是 miss
```

因为第一个还没搬完。

---

我们应该做：

```text
Core 0:
    COPY_IN(X) MISS
    ────────────────完成
                    ↓ L2 insert

Core 1:
                       COPY_IN(X) HIT

Core 2:
                            COPY_IN(X) HIT
```

所以条件应该是：

\[
t_{\text{leader finish}}
<
t_{\text{follower issue}}
<
t_{\text{FIFO eviction}}
\]

而不是“同时”。

---

## 可以定义 Cache reuse distance

若 leader 插入 Tensor \(x\) 后，到 follower 再访问之间，新插入缓存的数据总量为：

\[
D_x=
\sum_{\tau\in \text{between}} size(\tau)
\]

若：

\[
D_x<1MB
\]

则大概率保持命中。

于是 P3 变成：

# **Core Partition + Cache-aware Topological Ordering**

这非常有论文价值。

# 十五、P3 可以使用三资源池 lower bound

我们可以写：

\[
LB_3
=
\max


迁移到了：

```text

```

这个论文故事就很完整。
